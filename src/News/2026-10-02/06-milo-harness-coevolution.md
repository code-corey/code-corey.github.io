# MILO: Automated Harness Discovery via Orchestrated Multi-Agent Evolution（MILO：多智能体进化自动搜索最优 Agent Harness）

> 📅 2026-10-02 | 🏷️ 前沿论文 | ⭐ HF upvotes 15
> 🔗 原文：https://huggingface.co/papers/2609.38349

## 是什么

这篇论文研究 Agent 工程中被讨论最少、却影响最大的环节：**harness（脚手架）设计**——围绕模型的那一整套执行控制与环境交互机制（提示词、工具编排、技能、循环策略等）。论文指出 harness 设计强烈影响长程任务性能，但它的组合搜索空间巨大、人工调优成本高，且换模型就要重来。现有自动化方法搜索面窄、容易陷入局部最优。作者提出 **MILO（Meta-evolutionary Island Orchestration，元进化岛屿编排）**：同时共演化"harness 本身"和"发现 harness 的搜索策略"。

## 🔍 小白解读

### 先说几个词

- **Harness（脚手架）**：包在大模型外面的那套工程系统——怎么给模型提示、给它哪些工具、失败怎么重试。同一个大脑，装不同的"身体"，干活能力天差地别。
- **长程任务**：要连续干几十步、几小时才能完成的事，比如"深度调研写报告"。任何一步走偏都会滚雪球。
- **组合搜索空间**：可选配置的排列组合多到爆炸。比如 10 个环节各有 5 种做法，就是近千万种组合。
- **进化搜索**：模仿生物进化的优化方法——随机生成一批方案，留下好的，变异杂交再生成下一批。
- **岛屿模型**：把进化分成几个互不往来的"岛"各自演化，定期让岛间移民，避免所有方案挤在同一个小山头（局部最优）。

### 这篇到底在说什么

大家都在卷"哪个模型更聪明"，但这篇论文说：很多时候决定 Agent 干活好坏的，是外面那层"脚手架"搭得好不好。问题在于脚手架的参数和结构多到没人调得过来——提示词、工具组合、重试策略、技能库……组合爆炸，而且模型一升级，原来调好的可能全部作废。人工调就像在千万亩的玉米地里靠脚找最高那株。MILO 的做法是让计算机自己"育种"：同时开好几个岛，每个岛用自己的策略进化出一批 harness 方案，定期交换好基因，而且连"怎么搜索"这件事本身也在进化。打个比方，这不是派一个勘察员找路，而是派好几支风格完全不同的探险队分头探索，还让各队定期开会交流哪条路线好走。

### 这跟普通人有什么关系

你用到的每一个 AI 助手产品，背后都有这么一层"脚手架"。这类自动化调优技术成熟后，AI 产品在复杂任务上的稳定性会明显变好、价格也可能因为效率提升而下降。对普通用户是"AI 突然变靠谱了"的体感。

## 为什么值得架构师关注

这直接指向 Agent 平台团队的**最大隐性成本**：harness/prompt/skill 调优的人力投入，以及模型升级后的重新调优（paper 明确点名这个痛点"must be repeated as models change"）。具体影响：① 若你们维护多套 Agent 流水线，MILO 的"共演化 harness + 搜索策略"思路可用于评估自建自动调优管线的可行性——哪怕只落地"变异-评测-保留"的最简进化环；② 评测基建是前置条件：自动进化需要可自动打分的任务集，没有 eval 就没有搜索；③ 选型视角：未来 Agent 框架的竞争力可能从"预置了多少功能"转向"自适应调优能力"，选型时把这一维度加上。

## 核心内容

- 论文核心主张：harness 设计对长程 Agent 性能影响巨大，但其组合空间人工无法覆盖，且随模型更迭需要重复投入。
- 现有自动化方法的局限：只优化提示词/技能等局部组件，或搜索策略过于固定、易陷入局部最优。
- MILO 方案：Meta-evolutionary Island Orchestration，多岛屿并行进化 + 岛间迁移，且对"搜索策略本身"做元层级的共演化。
- HF upvotes 15，热度中等但主题稀缺——harness 自动化的系统化方法在论文界还很少见。

## 行动建议

Agent 平台团队值得精读：先自查三个问题——你们的 harness 配置有多少可枚举的维度？有没有可自动评测的任务集？模型升级后 harness 的重新调优花掉多少人力？若答案分别是"很多/没有/很多"，这篇论文的思路（哪怕简化实现）值得排期试点。短平快的做法是先建 eval 集 + 对单个环节（如重试策略）做网格搜索，验证收益后再上进化搜索。
