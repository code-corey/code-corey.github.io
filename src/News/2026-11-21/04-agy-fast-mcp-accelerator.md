# agy-fast：为 Google Antigravity 降本增效的 MCP 加速插件（省 34% 轮次 / 31% token）

> 📅 2026-11-21 | 🏷️ 值得研究的仓库 | ⭐ 164 Star（7 天爆发窗口，11-19 创建，TypeScript，MIT License，经 GitHub API 核实）
> 🔗 原文：https://github.com/INK-Q/agy-fast

## 是什么

一个面向 **Google Antigravity**（谷歌的 agentic 开发环境，覆盖 CLI/Desktop/IDE 形态）的**非侵入式 MCP 加速插件**：通过优化 agent 与模型之间的上下文传递，官方给出的实测数据为——LLM 交互轮次减少 34%、token 配额消耗减少 31%、上传流量减少 40%，且不改变 Antigravity 原生界面与代码 diff 行为。项目用 TypeScript 编写，MIT 协议，两天获得 164 Star。

## 🔍 小白解读

### 先说几个词

- **Google Antigravity**：谷歌推出的「智能体优先」开发环境，AI agent 可以自主写代码、跑测试、开浏览器验证，开发者更多是下需求和验收。
- **Token 配额**：AI 按处理文本量（token，大致是字词碎片）计费/计量。agent 干活越多、来回上下文越大，token 消耗越猛——这是 agent 编码工具最大的隐性成本。
- **轮次（Turns）**：agent 完成任务需要与模型交互的来回次数。轮次越多，越慢也越贵。
- **非侵入式（Non-invasive）**：不改动工具本体代码，以插件/代理方式在外围工作，升级不易被冲掉。

### 这篇到底在说什么

Agent 编码工具很烧钱：AI 每做一小步就要把大量上下文（文件、diff、日志）重新喂给模型，其中很多是重复和冗余的。打个比方：你每次跟同事沟通都要把整栋楼的图纸重发一遍，其实他只需要看改了哪一页。agy-fast 做的就是这个「只发改动那页」的优化——在 agent 与模型之间拦截和精简上下文传输，官方数据显示轮次、token、流量三个硬指标都降了三成左右，而 Antigravity 本身的使用体验不变。对一个重度使用 agent IDE 的团队，三成的 token 节省直接就是三成的 API 账单。

### 这跟普通人有什么关系

用 AI 编码工具的个人开发者，订阅/配额能多撑一倍时间；小公司用 agent 干活的预算门槛明显下降；这类「外围优化层」的思路对所有 AI 工具重户都适用。

## 为什么值得架构师关注

1. **Agent 成本工程成为独立层**：该项目证明「上下文传输优化」可以做成与 IDE 解耦的独立中间件，AI 平台团队的成本治理工单里应新增这一层。
2. **三个可复现的硬指标**：-34% 轮次、-31% token、-40% 上传流量都是可以在自己工作负载上复测的量化声明——这比大多数「提效」项目的模糊宣传更可验证。
3. **非侵入式架构的价值**：不 fork 不改源码的插件形态，升级维护成本低，适合作为企业内试点；但同时也意味着其优化对上游版本变化敏感。
4. **适用边界**：只针对 Antigravity 生态；其上下文精简思路（去重、增量传输）对自研 agent 系统有直接借鉴价值，但需要自己实现。

## 核心内容

- 定位：Google Antigravity（CLI/Desktop/IDE）的非侵入式 MCP 加速插件。
- 官方实测数据：LLM 轮次 -34%，token 配额 -31%，上传流量 -40%。
- 声明不改变 Antigravity 原生 UI 与 diff 行为，即优化对使用者透明。
- 技术栈 TypeScript，MIT 协议，11-19 创建、两天 164 Star（GitHub API 11-21 核实：164 stars，非 fork）。
- 供应链提示：第三方插件会经手你与模型之间的全部上下文，**企业引入前需审查其数据流向与遥测行为**。

## 行动建议

- **怎么评估试用**：选一个中等规模的测试仓库，记录基线（每任务轮次/token/时长），安装 agy-fast 后跑同一批任务对比三项指标是否与官方声明吻合；同时用代理抓包确认其只做精简、无额外外传。
- **引入条件**：个人/小团队可即刻试用；企业引入建议先过安全审查（依赖审计、数据流分析），并锁定版本、关注上游 Antigravity 更新后的兼容性。
- **自研借鉴**：如果你的团队自建 agent 工作流，把「上下文增量传输 + 去重」作为 P1 优化项，目标参考值即为 30% 量级的 token 削减。
