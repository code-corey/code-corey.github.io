# IQuest-Q1: Advancing Foundation Capabilities for Agentic CLI Systems（IQuest-Q1：面向 Agentic CLI 系统的基座能力）

> 📅 2026-10-25 | 🏷️ 前沿论文 | ⭐ HF upvotes 91
> 🔗 原文：https://huggingface.co/papers/2610.30949

## 是什么

IQuest-Q1 是一个面向 agentic CLI 系统（命令行智能体）的稀疏 MoE 基座模型：总参数 320B，每次推理仅激活 15B。论文完整公开了三阶段训练流程——稳定高效的预训练（Stable SplitNorm + Muon 优化器 + muP，二阶段课程增加代码数据占比）、精细的中期训练（跨领域数据扩展、渐进式上下文延长）、多脚手架多版本的后训练。HF 上获 91 赞，是当期 agent 方向最受关注的论文之一。

## 🔍 小白解读

### 先说几个词

- **MoE（混合专家）**：模型内有很多「专家小网络」，每个问题只叫醒相关的几个，省钱又保持大容量。
- **总参/激活参数**：总参数像全公司人数，激活参数像每次实际出工的人数——15B 激活意味着推理成本接近 15B 模型。
- **Agentic CLI**：在终端里自主干活的 AI（读代码、改文件、跑命令的那种）。
- **脚手架（Scaffold）**：包裹模型的工程外壳——工具调用、循环规划等让模型能持续干活的框架。
- **Muon / muP**：新型优化器与参数化方法，用于让超大模型训练更稳定、更省算力。

### 这篇到底在说什么

打个比方：市面上大多数「agent 模型」其实是通用聊天模型兼职干的，就像让前台顺手记账。IQuest-Q1 则是从员工招聘（预训练数据偏代码与任务）、岗前培训（中期训练拉长上下文）、实战演练（多脚手架后训练）全流程按「终端智能体」这个岗位定制的。320B 的总参数给了它足够的「知识储量」，15B 的激活参数让响应成本不至于失控。论文把三阶段的配方都写了出来，对研究者和工程团队都是可复用的参考。

### 这跟普通人有什么关系

未来你用的编程助手、运维机器人，如果底层换成这类 agent 专用模型，同样的价格可能换来更少的出错和更快的完成速度——因为模型本身就是为了「连续干活」训练的，而不是为了聊天。

## 为什么值得架构师关注

- 「agent 基座专用化」是清晰的趋势信号：选型时「通用模型 benchmark 分数」的参考价值下降，agent 环境下的任务完成率、工具调用成功率权重应上调。
- 320B/15B 的稀疏比例提供了自托管成本的锚点：若权重开放，单节点或小集群部署一个 agent 基座成为可能，值得与 API 方案做 TCO 对比。
- 三阶段训练配方（尤其多脚手架多版本后训练）对自研 agent 微调管线有直接借鉴意义：后训练要覆盖你实际使用的脚手架形态，而不是只测裸模型。

## 核心内容

- 模型规格：稀疏 MoE，320B 总参 / 15B 激活，面向 agentic CLI 系统（据摘要）。
- 预训练：Stable SplitNorm + Muon + muP，两阶段课程，第二阶段提高代码数据配比，保持安全与最优学习率间的稳定裕度（据摘要）。
- 中期训练：跨领域、跨格式扩展数据配比，渐进延长上下文（据摘要）。
- 后训练：多脚手架、多版本（据摘要）。
- 权重开源与否未在摘要中说明，需跟踪官方发布。

## 行动建议

做 agent 平台或重度使用 coding agent 的团队：一是跟踪该模型权重发布与第三方评测（尤其工具调用成功率、长任务完成率），作为 agent 基座选型的候选项；二是借其训练思路审视自家微调流程——如果后训练环境与生产脚手架不一致，就是当前最值得修的偏差源。
