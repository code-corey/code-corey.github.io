# SoMarkAI/OXR: An open-source document parsing model with SOTA accuracy and speed（OXR：开源文档解析模型）

> 📅 2026-10-25 | 🏷️ 值得研究的仓库 | ⭐ ⭐570（慢热发现，30 天窗口，2026-10-05 创建，Python）
> 🔗 原文：https://github.com/SoMarkAI/OXR

## 是什么

OXR 是一个开源的文档解析模型（Python），作者宣称在精度与速度上达到 SOTA，并在训练后（post-training）阶段采用了「RSI 循环」的方法。仓库创建于 2026-10-05，约 20 天积累 570 星——不是一周爆红的类型，而是持续爬升的慢热项目，本期仓库类目的「慢热发现」。

## 🔍 小白解读

### 先说几个词

- **文档解析（Document Parsing）**：把 PDF、扫描件、报表这类「给人看」的文件，转成机器能用的结构化文本/表格。
- **RAG（检索增强生成）**：先从资料库里检索相关内容，再让大模型基于内容回答，是企业 AI 落地最常用的架构。
- **SOTA**：State of the Art，公开评测中的最好水平（注意：此处为作者自述，需自行验证）。
- **RSI 循环**：递归自我改进——模型输出经过评估后反馈回训练/生成流程再迭代（据仓库描述，具体实现需看代码）。

### 这篇到底在说什么

打个比方：企业里的资料大多是 PDF 合同、扫描发票、图文混排的报告，直接喂给大模型就像把撕碎的报纸塞进碎纸机反向拼图——格式乱、表格歪、页眉页脚干扰大。文档解析模型就是专职的「拆文件员」，把内容拆得整整齐齐再交给下游的 RAG 系统或数据管线。OXR 的卖点是两件事同时做到：拆得准（精度）和拆得快（速度），并且声称训练方法上有新意（RSI 循环）。20 天 570 星的爬升曲线说明社区对「开源、能自部署」的文档解析方案有真实渴求。

### 这跟普通人有什么关系

只要公司要做「上传 PDF 问答机器人」「合同智能审阅」「发票自动入账」，背后都需要文档解析。这块过去要么用商用 API 按页付费，要么开源自建效果一般；多一个高质量开源选项，意味着数据不出门、成本可控成为可能。

## 为什么值得架构师关注

- 文档解析质量直接决定 RAG 系统上限：检索召回再准，解析丢了的表格也找不回来。在 ingestion 管线选型中，OXR 提供了「自部署 + 声称 SOTA」的新候选。
- 成本视角：自托管解析模型可以把按页计费的 API 成本转换为 GPU 资源成本，对文档量大的企业（金融、法务、医疗）有明确的 TCO 计算空间。
- 「RSI 循环做 post-training」若经验证有效，对内部微调管线也有方法论参考价值。

## 核心内容

- 定位（据仓库描述）：开源文档解析模型，精度与速度声称 SOTA；训练后阶段采用 RSI 循环。
- 语言/形态：Python；2026-10-05 创建，至收录时 ⭐570（本期唯一入选的 30 天慢热窗口仓库）。
- 许可与模型权重发布情况需进仓库确认（缓存未含 license 字段）。
- 无官方 benchmark 报告链接，SOTA 声明目前仅为作者表述。

## 行动建议

正在自建或重构文档摄取管线的团队，值得安排半天做独立评测：用自己业务的真实文档集（扫描件、复杂表格、多栏版式各占一定比例）对比现有方案（商用 API 与现用开源模型），重点看表格结构还原率、页眉页脚噪音、吞吐时延。验证通过再考虑替换；纯观望团队可 star 跟踪其 issue 区活跃度与权重发布动态。
