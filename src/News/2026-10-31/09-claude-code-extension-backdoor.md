# Backdoor in Claude Code for VS Code extension on the Cursor Marketplace（Cursor 插件市场现带后门的 Claude Code 扩展）

> 📅 2026-10-30 | 🏷️ 安全 & 评测 | ⭐ HN 747 分 / 467 评论（当日全站最高之一）
> 🔗 原文：https://phorion.io/blog/offical-claude-code-vsx-compromise/

## 是什么

一个自称「官方」的 Claude Code VS Code 扩展被发现在 Cursor 插件市场上带有后门分发，成为当日 HN 最热话题（747 分/467 评论）。多家安全渠道交叉确认这是一起针对 AI 开发工具链的供应链攻击：Ars Technica 报道恶意扩展在市场上架近 12 小时；DoublePulsar 分析称攻击者通过入侵 Anthropic 相关渠道向全球开发者笔记本投递远程访问木马（RAT）；Step Security 的技术分析指出后门会在开发者机器上植入持久化 SSH 后门；WIRED 则报道称数千台设备受到影响。

## 🔍 小白解读

### 先说几个词

- **供应链攻击（Supply chain attack）**：黑客不直接攻击你，而是污染你下载软件的「上游渠道」——就像不往你家投毒，而是往超市货架上的商品里投毒，你正常购物就把危险带回家了。
- **插件市场（Marketplace）**：VS Code、Cursor 等编辑器的「应用商店」。开发者习惯信任商店里的东西，这恰恰是被利用的信任链。
- **后门（Backdoor）**：软件里藏的秘密通道，攻击者可以绕过正常登录直接进出你的电脑。
- **远程访问木马（RAT）**：让攻击者能像坐在你电脑前一样远程操作的恶意程序。
- **持久化 SSH 后门**：SSH 是远程登录服务器的标准工具，把攻击者的密钥悄悄加进你的 SSH 配置，即使你删掉木马，他还能从后门进来——类似于换了门锁但贼手里还留着备用钥匙。

### 这篇到底在说什么

打个比方：Claude Code 是现在很多程序员的「AI 编程搭子」，大家习惯了从插件市场一键安装它。这次攻击者把一个看起来一模一样的「官方版」放上了 Cursor 的插件市场，开发者像往常一样点安装，结果装回来的是带后门的版本——短短近 12 小时的窗口期里，装了它的开发者电脑就等于给黑客留了一扇门，而且这扇门（SSH 持久化后门）重装系统都不一定关得上。这件事的震撼点在于目标选择：不是普通软件，而是「AI 工具链」本身——它攻击的是全世界防御能力最强的那批开发者。HN 上 467 条评论的核心争论是：插件市场的审核机制形同虚设，AI 编码工具的爆发让「开发者机器」成了高价值靶子，而整个生态的信任模型还停留在十年前。

### 这跟普通人有什么关系

普通用户虽然不装开发插件，但你的公司里总有人装——而开发者电脑上通常有生产环境的密钥、代码仓库权限和内网通道。一台开发者笔记本沦陷，攻击者就能顺藤摸瓜进入公司内网。这是每个用了 AI 编程工具的团队都必须知道的事件。

## 为什么值得架构师关注

1. **开发端信任模型失效**：本次事件证明「来自官方名字的插件 ≠ 官方出品」。企业需要立即建立 IDE 扩展白名单/审核机制，把 IDE 插件纳入与 npm/pip 依赖同级的供应链治理范畴。
2. **AI 工具链成为高价值靶标**：Claude Code / Cursor 这类工具拥有读写代码、执行命令、访问凭证的深度权限，是攻击者的理想入口。对 agent 类开发工具的权限授予（文件系统、网络出口、凭证访问）需要做最小化收敛。
3. **凭证轮换的紧迫性**：SSH 持久化后门意味着机器可能早已失守。涉事期间安装过相关扩展的开发者机器，其上的私钥、令牌、云凭证都应视为已泄露并轮换，这应作为正式安全事件启动响应流程。

## 核心内容

- 名为「Claude Code for VS Code」的扩展在 Cursor Marketplace 带后门分发，被多来源确认非 Anthropic 官方出品。
- Ars Technica：恶意扩展在市场上架近 12 小时后才被处理。
- DoublePulsar：定性为供应链攻击，向全球开发者设备投递远程访问木马。
- Step Security 技术分析：后门在开发者机器上建立持久化 SSH 后门。
- WIRED：报道称数千台设备受影响；HN 相关讨论热度极高（两条相关帖合计约 1400 分），显示行业震动级别。

## 行动建议

- 立即排查：让全员执行「已安装扩展清单」审计，重点核对 Claude Code 相关扩展的来源、发布者 ID 与安装时间；涉及涉事窗口期的机器按「已失守」处理——轮换 SSH 密钥、云凭证、git token，并检查 authorized_keys 与异常出站连接。
- 机制建设：本周内把「IDE 扩展白名单 + 发布者核验」写进开发环境基线；对 agent 类开发工具的网络出口做监控告警。
- 了解即可：事件仍在演进中，IOC（失陷指标）与完整时间线以 phorion.io、DoublePulsar 与 Anthropic 官方通告的后续更新为准。
