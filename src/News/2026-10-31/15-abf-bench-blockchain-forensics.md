# ABF-Bench: A Verifiable Benchmark for Agentic Blockchain Forensics（链上取证智能体的可验证基准）

> 📅 2026-10-30 | 🏷️ Web3 & Crypto | ⭐ HF upvotes 3（新上线，Web3×AI 交叉方向）
> 🔗 原文：https://huggingface.co/papers/2610.23656

## 是什么

ABF-Bench 是一个把「区块链资金追踪取证」变成智能体（Agent）可验证任务的交互式基准。洗钱者会拆分、跨链交换、经混币器切断资金路径，调查人员必须不断调整追踪策略——ABF-Bench 要求 Agent 像真实调查员一样工作，且每一步声称的资金移动都必须引用自己检索到的链上记录作为证据，使整个调查过程可以被独立复核。

## 🔍 小白解读

### 先说几个词

- **区块链取证（Blockchain forensics）**：追踪链上赃款流向的数字刑侦工作，币安 63 亿美元失窃后的追赃就是这类工作（见本期另一篇报道）。
- **混币器（Mixer）**：把很多人的币混在一起再分出去，切断「这笔币是谁的」的线索，像把不同人的钞票放进同一台洗钞机再随机分发。
- **跨链/桥（Bridge）**：把资产从一条区块链转移到另一条链的通道，黑客常用它让追赃难度翻倍。
- **可验证基准（Verifiable benchmark）**：不只给 Agent 打分，还要求它的每个结论都附带可查证的证据——因为区块链的公开账本永久记录了所有转账，答案对不对可以客观复核。
- **Agent（智能体）**：能自主调用工具（比如查询链上数据）、多步推理、动态调整策略的 AI 系统。

### 这篇到底在说什么

打个比方：让 AI 当链上「刑警队」，去追一群不断换车、换路、换车牌的逃犯（拆分、跨链、过混币器的赃款）。以往让 AI 做这种任务，最大的问题是「你不知道它的答案是推理出来的还是编的」。ABF-Bench 的聪明之处在于利用了区块链的独特性质——所有转账都永久公开记录在案——所以它规定：AI 每声称「资金从 A 流到了 B」，必须附上链上记录作为证据，整个调查就像带着完整案卷的司法程序，任何人都可以逐步复核。这既是给「链上取证 Agent」定的能力考试，也示范了一种「带证据链的 Agent 任务」设计范式。它与本期的币安失窃报道正好互为印证：历史上最大规模的追赃行动正在进行，这类自动化取证能力的需求处于历史高位。

### 这跟普通人有什么关系

赃款追得回与否，直接关系到被盗资金的赔付可能性——更好的取证工具意味着更大的追回概率。对企业来说，「AI 的结论必须附证据」这个模式正在从区块链取证扩散到金融合规、审计等所有需要「可核查结论」的领域。

## 为什么值得架构师关注

1. **「可验证 Agent 任务」的设计范式**：ABF-Bench 的核心设计——结论必须引用检索到的原始记录——可以泛化为企业级 Agent 的评测与运行规范：凡涉资金、合规、审计的 Agent 输出，都应强制附带可机读的证据引用，这一模式可直接移植到内部风控/审计 Agent 的验收标准中。
2. **Web3×AI 交叉的落地信号**：链上取证是少数「数据天然可验证 + 任务价值极高」的 Agent 应用场景，比一般领域的 Agent 更容易做到可问责。合规科技（RegTech）、交易所安全团队值得把「Agent 辅助追踪」纳入技术雷达。
3. **评测资产的建设思路**：交互式、抗对抗（对手会变招）的基准设计，比静态题库更接近真实攻防，做内部 Agent 评测时可借鉴其「动态场景 + 证据校验」的结构。

## 核心内容

- 提出 ABF-Bench：将区块链资金追踪定义为「证据可验证」的交互式 Agent 任务。
- 核心机制：Agent 每声称一笔资金移动，必须引用其检索到的链上记录，结论可被独立复核。
- 任务设定贴近真实对抗：洗钱者会拆分资金、跨链交换、经混币器与托管服务切断路径，Agent 需动态调整追踪策略。
- 论文强调区块链公开账本的不可篡改性使大部分调查过程天然可验证——这是该基准区别于普通 Agent 基准的关键。
