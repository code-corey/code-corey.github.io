# Claude Code regularly sends each background agent's transcript to its model（Claude Code 定期向模型回传后台智能体的完整对话记录）

> 📅 2026-10-29 | 🏷️ 安全 & 评测 | ⭐ HN 558分/224评论
> 🔗 原文：https://gist.github.com/flamerix-ai/c3905705cc4205e5de3011fa2e74efce

## 是什么
社区发布的一项调查（GitHub Gist，HN 558 分/224 评论）显示：Claude Code 在运行后台智能体（background agents）时，会定期把每个子智能体的完整对话记录（transcript）发送给其背后的模型。这意味着你代码库的内容、终端输出、以及会话中出现过的敏感信息，会作为上下文持续外发——多智能体工作流的隐私与合规边界问题被摆上台面。

## 🔍 小白解读
### 先说几个词
- **后台智能体（background agent）**：在「看不见的窗口」里自主干活的 AI 员工，比如同时跑在后台改代码、跑测试的多个 Claude Code 子任务。
- **transcript（对话记录）**：智能体工作全程的完整流水账——它读了哪些文件、执行了哪些命令、看到了哪些输出。
- **数据外发面（data egress surface）**：你的数据可能流出你控制范围的全部通道。通道越多越隐蔽，越难审计。
- **上下文（context）**：模型回答问题前「要看」的全部材料。记录回传给模型，本质就是把材料再喂一遍。
- ** Orchestrator（编排器）**：指挥多个子智能体的「主管」，由它决定把什么信息交给谁。

### 这篇到底在说什么
很多人对 AI 编码工具的想象是：一个助手，我说一句它写一段。但现在流行的用法是「一个主管带着一群后台员工」：你派一个任务，主管把活拆给多个后台智能体并行干。这份调查显示，主管会定期把每个「员工」的完整工作记录——包括读过的代码、跑命令的输出——打包发给模型。对模型来说这是为了「记住全局、协调进度」；但对用户来说，这意味着外发的数据量远超你的直觉：你以为只发了一段提示词，实际发的是后台所有智能体的完整工作流水账。如果流水账里混进了密钥、内网地址、客户数据，它们也随之离开了你的边界。这不是「黑客攻击」，而是工作机制本身的隐私含义，之前很少有人把它讲清楚。

### 这跟普通人有什么关系
如果你在公司用 AI 编码工具，它处理的可能不只是你个人的小项目，还有公司代码。了解「哪些内容会被发送出去」，是每个使用者的知情权，也是企业制定 AI 使用规范的第一课。

## 为什么值得架构师关注
- **Agent 架构的数据流审计缺失**：多智能体系统里「谁把什么发给了谁」普遍没有可视化，上生产前必须补一张完整的数据流图（含 transcript 回传路径）；
- **敏感信息治理**：密钥扫描、路径排除、环境变量脱敏要在 agent 工具链入口完成，而不是靠事后追查；
- **合规基线更新**：需要按「transcript 可能整体外发至模型服务商」这一最坏假设重审数据分级策略与企业版数据治理选项（留存、训练豁免等以官方条款为准）。

## 核心内容
- 调查发现（Gist，2026-10-29）：Claude Code 会定期把每个后台智能体的 transcript 发送给其模型（HN 558 分/224 评论）；
- 影响：多智能体并行时，外发内容为「全部子任务工作记录」的聚合，量级远超单次提问的直觉；
- 风险面：代码片段、命令输出、会话中出现的敏感信息随记录外发；
- 定性：工具工作机制的隐私含义，属社区独立观测，非官方安全公告；官方文档与回应为准。

## 行动建议
- 已在用多智能体编码工具的团队：立即盘点智能体配置——工作目录、可读路径、环境变量，清除敏感项后再继续使用；
- 平台/安全团队：把「agent transcript 外发」纳入数据出境与供应商评估清单，明确企业版数据处理协议覆盖范围；
- 所有开发者：养成习惯——让 agent 沾手生产数据前，先问一句「这些内容会以什么形式发到哪里」。
