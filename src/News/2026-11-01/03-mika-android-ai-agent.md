# Mika: An on-device AI agent for Android（Mika：你手机上的私人 AI 助理）

> 📅 2026-10-31 | 🏷️ 值得研究的仓库 | ⭐ 2,724 Stars（创建于 2026-10-29，7 天爆发窗口）| 语言：Kotlin
> 🔗 原文：https://github.com/wangzan101/Mika

## 是什么

Mika 是一个爆发中的开源安卓应用：你说一句话，它替你操作手机 App 和网页把事办成——比如「总结一下群里今天聊了啥」「30 美元以内、4.5 星以上的充电器，挑好加购物车，停在结账前」。它在一块看不见的「后台屏」上干活，不占你的手机屏幕；仓库创建仅两天多就冲到 2,724 Star，Apache-2.0 协议完全开源。

## 🔍 小白解读

### 先说几个词

- **端侧 Agent（On-device agent）**：AI 助理跑在你自己的手机上，而不是云厂商的机房里。相当于把「秘书」从总部派驻到你家，通信自由、隐私可控。
- **后台屏（虚拟屏）**：安卓系统允许应用开一块看不见的「分屏」，Mika 就在上面像人一样打开 App、看屏幕、找按钮、点击输入——你照常刷你的手机，互不打扰。
- **视觉操作（读屏）**：不依赖 App 官方开放接口，靠「看屏幕 + 找按钮」来操作，因此理论上什么 App 都能用，不需要对方配合适配。
- **BYOK（自带 Key）**：Mika 没有自己的服务器，你在设置里填自己买的模型 API Key（DeepSeek、通义千问、Kimi、OpenAI 等），数据只发给你选的模型服务商。
- **询问模式**：默认只有花钱的动作（下单、付款）会先问你，其他事直接办完；也可以切换成完全自主模式。

### 这篇到底在说什么

打个比方：Mika 像一个住在你手机里的隐形助理。你说「帮我订明天早上两个闹钟」「每天早上 8 点看天气，下雨才告诉我」，它就在后台那块看不见的屏幕上打开相应 App，一步步点、翻、读、填，做完向你汇报；遇到登录、验证码、付款这类敏感步骤会主动交还给你操作。它内置了几十个中国用户常用 App 和网站的操作知识（微信、抖音、B 站、小红书、BOSS 直聘、微博、知乎、淘宝系、Amazon 等），没写过的 App 理论上也能靠「看屏找按钮」通用操作。每个对话还配一个 Linux 沙箱，能跑 Python 和脚本处理你发来的文件。它越用越懂你：记住你的偏好，把办成的事总结成「技能」下次复用。隐私设计上没有 Mika 服务器，API Key 和记忆都加密存在手机本地。需要安卓 11 以上，操作 App 功能推荐安卓 14+，配一次无线调试即可启用。

### 这跟普通人有什么关系

对普通用户：抢票、比价、凑满减、总结群聊这类「App 搬砖活」可以开始交给它，付款前它会停下来问你。对注重隐私的人：没有中间服务器、数据只发给自选的模型商，是目前端侧助理里比较干净的设计。对手机是安卓 11 以下或 iPhone 的用户：暂时用不了，但这类产品形态大概率会快速普及到各平台。

## 为什么值得架构师关注

- **端侧 Agent 的参考架构**：虚拟屏 + 视觉操作循环 + 本地沙箱 + 本地记忆的完整实现，是研究「无 API 依赖的 GUI Agent」落地细节的优质样本，Kotlin 代码可直接读。
- **隐私与合规边界设计**：无自建服务器、BYOK、敏感步骤人工接管的分层设计，可直接借鉴到企业内部移动助手类产品的合规方案里。
- **移动端 Agent 工程约束**：安卓版本门槛（11/12/14+）、arm64 沙箱、无线调试配对——这些真实约束是移动 AI 功能规划时的现实清单。
- **生态信号**：两天半 2.7k Star 的爆发速度说明「替你操作 App」的需求远未饱和，且开源端侧方案开始与厂商的 App-Agent API 路线并行竞争。

## 核心内容

- 定位：安卓端侧私人 AI 助理，一句话驱动，替你操作 App、上网、办事；后台虚拟屏执行，不占用用户屏幕。
- 操作方式：像人一样读屏找按钮，不依赖 App 开放接口；内置 20+ 常用 App 与 17 个网站的操作知识，未覆盖的也可通用操作。
- 隐私模型：无 Mika 服务器，用户自配模型服务（DeepSeek/千问/Kimi/智谱/OpenAI/Anthropic 等预设，兼容 OpenAI/Anthropic/Gemini 接口），Key 与记忆本地加密存储。
- 能力边界：登录、验证码、付款等敏感环节交还用户；默认询问模式（仅花钱先问）；支持定时与条件任务、随时插话与撤回。
- 工程细节：Kotlin 开发，Apache-2.0；每对话一个 Linux 沙箱（arm64，Python/Node/shell）；支持电脑端通过 CLI/Skill/MCP 派任务；创建两天多获 2,724 Star。

## 行动建议

1. 移动端团队可实机试用评估：重点测「后台屏」在主流国产 ROM 上的兼容性与耗电，跑一遍仓库提供的 12 项兼容性自检。
2. 架构上值得精读其读屏操作循环与「技能沉淀」机制，评估能否迁移到企业内部移动运维/巡检场景。
3. 若产品涉及第三方 App 自动化，注意其 README 自身提示：自动操作第三方 App 可能违反对方用户协议，商用前先过法务。
