# AMLChecker/monero-web-wallet: Self-hosted, non-custodial Monero web wallet（自托管非托管 Monero 网页钱包）

> 📅 2026-09-21 | 🏷️ Web3 & Crypto | ⭐ ⭐51（7天·低星独特项）
> 🔗 原文：https://github.com/AMLChecker/monero-web-wallet

## 是什么

GitHub 仓库 AMLChecker/monero-web-wallet（TypeScript，stars 51，创建于 2026-09-21）是一个自托管、非托管的 Monero (XMR) 网页钱包。官方描述为：「Self-hosted, non-custodial Monero (XMR) web wallet: dark responsive UI on top of the official monero-wallet-rpc. Keys stay on your machine, two-phase sending with explicit fee review, Windows quick start.」它在官方 monero-wallet-rpc 之上提供深色响应式界面，密钥不出本机。

## 🔍 小白解读

### 先说几个词

- **非托管（non-custodial）**：钱包只帮你管钥匙和发起交易，钱始终在链上你自己的地址里，服务商拿不到。好比自带保险箱，而不是把钱存银行。
- **自托管（self-hosted）**：这个钱包程序跑在你自己的电脑上，不部署在别人的服务器上。好比自己在家做饭，而不是下馆子。
- **RPC**：远程过程调用，程序间「打电话下指令」的标准方式。monero-wallet-rpc 是 Monero 官方提供的钱包控制接口。
- **环签名**：Monero 用来隐藏付款人的技术——把你的签名混进一群人里，外人看不出谁真正签了字。
- **手续费（Gas/fee）**：每笔链上交易付给网络的小费，金额直接影响交易确认速度和成本。

### 这篇到底在说什么

打个比方：很多网页钱包像「代客理财」——你把钥匙交给对方的网站；这个项目则是把钥匙锁在家里（密钥不出本机），只借用官方的遥控器（monero-wallet-rpc）操作链上资产。它做了三件值得称道的事：一是基于官方 RPC 封装界面而非自造密码学轮子，这是非常保守也正确的工程选择；二是密钥完全留在本机，做到非托管；三是发送交易采用「两阶段发送 + 手续费显式确认」——先组装交易让你看清金额和手续费，确认后才真正广播，而不是一键发出。第二点尤其值得夸：很多链上事故源于手滑点了确认，两阶段确认把「看清楚」和「发出去」拆成两步。

### 这跟普通人有什么关系

如果你用过任何加密货币钱包，「确认前能清楚看到手续费、确认后再广播」是值得养成习惯的安全范式。另外需客观提示：Monero 是隐私导向的加密货币（用环签名隐匿交易），在全球多地质于监管敏感区，企业若考虑采用，务必先做合规评估——这是事实性提醒，不是法律意见。

## 为什么值得架构师关注

第一，「两阶段发送 + 手续费显式确认」是可迁移到任意链的交易安全交互范式：组装态与广播态分离，天然适配审批流、多签预览、风控拦截。第二，封装官方 RPC 而非重写密码学逻辑，是钱包类工程的正确边界——UI 层创新、密码学层守旧。第三，「自托管 + 非托管」的架构区分值得产品团队对齐：非托管解决资产控制权，自托管解决数据主权与信任面，两者正交，需求不同选型不同。

## 核心内容

- 基于官方 monero-wallet-rpc 封装，不自造密码学轮子，TypeScript 实现。
- 密钥不出本机：非托管 + 自托管，服务器侧不持有用户密钥。
- 两阶段发送：交易先组装预览、手续费显式确认后，才广播上链。
- 提供 Windows 快速启动，界面为深色响应式设计。
- 仓库 stars 51（7 天新增），低于本栏目常规 100 星门槛；入选因架构清晰可见、交易安全范式可迁移到任意链。
- 提醒：Monero 作为隐私币处于多国监管敏感区，企业采用前需合规评估。

## 行动建议

- 钱包/链上应用架构师：把「两阶段发送 + 手续费显式确认」直接纳入交互设计规范，尤其适用于大额与多签场景。
- 后端团队：参考「封装官方 RPC、密钥本机化」的分层边界，审视自家钱包是否有密码学自造轮子。
- 企业合规负责人：如涉及隐私币业务，先完成法域合规评估再谈技术选型。
- 普通用户：了解即可；使用任何钱包时养成「看清手续费再确认」的习惯。
