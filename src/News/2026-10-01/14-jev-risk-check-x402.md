# jev-risk-check-provider: x402 paid on-chain risk verdicts for AI agents（x402 按次付费的链上风险判定服务）

> 📅 2026-09-27 | 🏷️ Web3 & Crypto | ⭐ ⭐8（7天：09-27 创建）
> 🔗 原文：https://github.com/caiovicentino/jev-risk-check-provider

## 是什么

jev-risk-check-provider 是一个 TypeScript 开源项目：把链上风险判定做成按次收费的 API 服务——每次检查给出「签名的预支付风险判定（signed pre-payment verdicts）」，覆盖 OFAC 制裁名单筛查、钓鱼网站情报、交易模拟、drainer（盗窃套件）代码识别，以及自研的 EIP-7702 相关毒剂地址监控。计费两档：预付点数 $0.001/次，或通过 x402 协议按次支付（$0.0035 起）。项目于 09-27 创建。

## 🔍 小白解读

### 先说几个词

- **x402**：一个让「按次付费调 API」变成现实的开放协议（基于 HTTP 402 Payment Required 状态码的思想）：调用接口时用加密货币自动微支付，不用注册账号、不用签合同。好比高速收费站，过一次付一次。
- **OFAC**：美国财政部海外资产控制办公室，维护制裁名单——和名单上的人做交易，合规上等于踩雷。
- **Drainer（盗窃套件）**：一种诈骗工具包，诱导你签下恶意授权，然后把你钱包里的资产搬空。「drainer-kit 代码检测」就是识别这类恶意代码的特征。
- **EIP-7702 / 地址投毒（Poisoning）**：EIP-7702 是让普通钱包短期获得智能合约能力的以太坊升级；「投毒者」指往你的转账历史里撒假地址、等你转账时手滑选错的攻击者，「sweeper」则是盯着疏忽钱包自动扫货的机器人。
- **签名判定（Signed Verdict）**：服务方对检查结果附加自己的数字签名——结果可独立验证、不可抵赖，相当于体检报告盖了公章。

### 这篇到底在说什么

AI Agent 要替人管理链上资产，第一个问题就是：它怎么知道一笔交易、一个地址、一个网站是不是陷阱？这个项目给的答案是：把「风险判定」本身做成一门按次收费的生意。你（或你的 AI Agent）在签任何交易前，先花零点几美分问一次这个 API：这个地址干净吗？这笔交易模拟执行下来会怎样？对方是不是钓鱼？然后拿着一份带签名的判定结果再做决定。有意思的是它自己吃自己的狗粮：计费用 x402 协议——一个「过站付费」的微支付协议，Agent 调 API 时自动完成链上扣款，全程无账号。这个项目的样本价值在于它同时踩中了三个趋势：AI Agent 的安全护栏需求（Agent 需要工具化的风险判断）、Web3 安全情报的商品化（风险数据按次售卖）、以及 x402 微支付协议的落地（机器间付费的真实用例）。8 个星说明它还很早期，但「问题定义」是完整且真实的。

### 这跟普通人有什么关系

加密诈骗最大的入口就是「授权签名」那一刻。这类风险检查服务成熟后，你的钱包 App 可以在签字前自动帮你查一遍「这一笔会不会把家底送人」——相当于转账前的反诈中心。对不用加密货币的人，这也是个预览：未来 AI 助手替你花钱时，背后就是这样的「风险检查 + 自动微支付」流水线。

## 为什么值得架构师关注

- **Agent 安全护栏的参考架构**：「行动前调用风险判定 → 拿签名结果 → 再执行」这个模式适用于所有涉及资金操作的 Agent，不限于链上——风控判定服务化是可复制的架构模式。
- **x402 微支付的首批真实用例**：机器间按次付费（Agent 调 API 自动扣款）是 AI×支付交叉的关键基础设施，值得跟踪其协议成熟度与费率结构。
- **安全情报的商品化定价信号**：$0.001/次的定价揭示了风险数据的单位经济——极低单价 + 海量调用，这类服务的壁垒在情报质量与误报率，不在价格。
- **EIP-7702 生态的衍生风险**：新协议能力（如 7702 委托）必然催生新的攻击形态（毒剂、sweeper 变体），安全监控需随协议升级同步演进。
