# Evolving to Match Capabilities: Improving Harness Self-Evolution via Skill Adaptation（技能要配得上模型）

> 📅 2026-10-28 | 🏷️ 前沿论文 | ⭐ HF upvotes 12
> 🔗 原文：https://huggingface.co/papers/2610.33024

## 是什么

这篇论文系统研究了 Agent Harness（智能体执行框架）的"自进化"问题：不更新模型权重，仅通过执行经验改进框架与技能包，效果如何？核心发现是——**技能的收益严重依赖模型能力档位**：能帮强模型涨 31.1 分的技能，套在弱模型上反而降 8.8 分。

## 🔍 小白解读

### 先说几个词

- **Harness（执行框架）**：包裹在大模型外面的"工作服"——工具调用、提示组织、流程控制这些让模型真正干活的脚手架。同一个大脑，穿不同工作服，干活效率天差地别。
- **Skill（技能包）**：预先写好的任务方法论文档，教 Agent 某类任务的标准打法（怎么查资料、怎么改代码、怎么验证结果）。
- **自进化（self-evolution）**：不重新训练模型，而是让框架和技能从执行经验中自动改进——相当于员工不换脑子，只优化工作手册。
- **能力分层**：不同参数量/代次的模型（如 GPT-5.6-luna 与 Gemma-4-E4B）之间存在明显能力梯度，适合前者的策略未必适合后者。
- **基准测试（benchmark）**：标准化的考卷，用来量化 Agent 在任务上的表现变化。

### 这篇到底在说什么

打个比方：你给马拉松冠军和普通跑者各配了一双顶级碳板跑鞋，冠军穿上破纪录（+31.1 分），普通跑者穿上却容易摔跤（−8.8 分）——鞋是好鞋，但脚力不够的人驾驭不了。这篇论文用 7 个模型、3 个基准、103 组"任务-技能"配对做了大样本验证，结论干脆利落：**技能包与模型档位之间存在匹配问题**，为强模型设计的技能对弱模型不仅可能无效，还可能有害。这直接推翻了"技能库一次建设、全员共享"的朴素设想。论文进一步研究如何做"技能适应"（skill adaptation）：让 harness 自进化时考虑当前模型的能力水平，把技能调整到与模型匹配的形态。对正在大规模部署 Agent 的团队来说，这篇论文等于提前踩了一个坑：技能资产管理不是复制粘贴，而是要跟模型选型绑定。

### 这跟普通人有什么关系

用 AI 工具时觉得"攻略没用甚至添乱"，可能不是攻略写得差，而是它为更强的模型写的。普通用户和小团队在抄别人的 Agent 配置时，要先确认配置作者用的模型和自己是不是一个档位。

## 为什么值得架构师关注

- **技能库治理**：内部 Agent 技能包必须带"模型兼容性矩阵"（哪档模型适用），否则升级/混用模型时会引入隐性回退——本文提供了量化证据（+31.1 vs −8.8 分）。
- **模型更换 ≠ 免费迁移**：切换基座模型时，harness 与技能包需要重新验收，版本管理要覆盖"技能×模型"二维矩阵。
- **成本-能力权衡新维度**：弱模型 + 无技能可能优于弱模型 + 强模型技能——"给小模型减负"有时比"给它上重型方法论"更省 token 且更稳。
- **评测流程设计**：技能上线前应做跨模型 A/B（至少覆盖主力与边缘两档模型），本文的 103 组配对方法可直接借鉴为内部评测模板。

## 核心内容

- 发现：harness 收益在模型间不均匀，帮助强模型的技能可能对弱模型无益甚至有害。
- 规模：7 个模型 × 3 个基准，识别出 103 组任务-技能配对，其中技能使 GPT-5.6-luna +31.1 分、使 Gemma-4-E4B −8.8 分。
- 方案：提出技能适应（skill adaptation）路径，让 harness 自进化与模型能力档位对齐。
- 论文编号 2610.33024，HF 每日论文 12 赞，属于本周 Agent 工程方向实证研究的代表作。

## 行动建议

1. 盘点现有技能包：为每个技能标注"验证过的模型档位"，未标注的视为未验证。
2. 在模型升级流程中加入技能回归测试：新模型上线前，跑一遍核心技能包的基准对比。
3. 若团队同时用强弱两档模型（云端旗舰 + 端侧小模型），按档位维护两套技能配置而非一套通用配置。
