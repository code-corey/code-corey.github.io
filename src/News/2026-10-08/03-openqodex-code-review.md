# OpenQodex: Open Source AI Code Review for Claude Code and Codex（推送前的开源 AI 代码审查闸门）

> 📅 2026-10-08 | 🏷️ 值得研究的仓库 | ⭐ 255（7天）
> 🔗 原文：https://github.com/openqodex/openqodex

## 是什么

OpenQodex 是一个 TypeScript 编写的开源 AI 代码审查工具，专门针对 Claude Code 和 Codex 产出的代码改动，在 push 之前做一道安全与质量闸门：先对改动行跑多类扫描器，再由独立的审查进程逐条复核发现，且不需要额外的 API key。

## 🔍 小白解读

### 先说几个词

- **Code Review（代码审查）**：别人提交代码后，由人或工具检查有没有问题再合入。类比：文章发表前的校对环节。
- **SAST（静态应用安全测试）**：不运行程序，直接扫描源代码里的安全漏洞。类比：不试驾，光看车检报告就发现刹车管漏油。
- **Secrets（密钥泄露）扫描**：检查代码里有没有不小心写进去的密码、API key 等敏感信息。
- **Lint**：检查代码风格和低级错误的工具，好比排版规范的自动纠错。
- **Push**：把本地写好的代码上传到远程仓库的动作——一旦推出去，别人就能看到。

### 这篇到底在说什么

现在很多人用 Claude Code、Codex 这类 AI 编程助手写代码，写得快，但 AI 生成的代码同样可能有安全漏洞、会不小心带上密钥。OpenQodex 想做的是那道「出门前的安检门」：在你把代码 push 上去之前，先只针对你改动过的那几行跑四类扫描——SAST 安全扫描、密钥泄露检查、依赖检查、lint。更巧妙的是它有两级架构：扫描器报出来的每一条发现，还会交给一个独立的审查进程去复核，审查进程能看到所有改动行，判断这条警报是真问题还是误报。这样能压掉扫描器常见的「狼来了」噪音。另外它不需要你再配额外的 API key，接入门槛低。项目 2026-10-02 创建，7 天内拿了 255 星，热度上升很快。

### 这跟普通人有什么关系

用 AI 写代码的普通开发者，等于多了一道免费自动安检，避免把密码或漏洞推上公共仓库。小团队不用采购商业扫描服务，也能拥有 push 前的基础安全门禁。

## 为什么值得架构师关注

- **流程卡点设计**：把安全检查放在 push 前（而非 PR 后），能把问题拦截在开发者本地回路里，修复成本最低。
- **两级复核架构**：「扫描器 + 独立复核进程」是控制误报率的实用模式，比单纯堆扫描规则更能降低告警疲劳，这一思路可迁移到自建 DevSecOps 流水线。
- **零额外密钥**：不需要额外 API key 意味着更少的凭证管理和泄露面，落地摩擦小。
- **增量扫描**：只扫改动行，反馈速度快，适合嵌入本地 hook 或 CI 的短超时窗口。
- **边界**：定位是对 Claude Code / Codex 改动的审查闸门，不能替代全量代码审计与人工安全评审。

## 核心内容

- 开源仓库：github.com/openqodex/openqodex，语言为 TypeScript。
- 面向 Claude Code 和 Codex 的改动，在 push 前执行代码审查。
- 扫描器覆盖四类：SAST、密钥（secrets）、依赖、lint，且只扫描改动的行。
- 采用两级架构：扫描器发现问题后，由一个独立审查进程复核每条发现，复核进程可获得全部改动行。
- 无需额外的 API key 即可运行。
- 2026-10-02 创建，⭐255（7 天窗口）。

## 行动建议

先在个人项目或非核心分支试跑：1）按仓库 README 安装并接入本地 pre-push hook；2）准备几个已知有漏洞 / 含假密钥的提交样本，验证扫描与复核是否准确命中；3）统计一周内的误报率，与团队现有扫描流程对比；4）确认无误报噪音后再考虑接入 CI 或推广到团队（具体安装方式以仓库 README 为准）。
