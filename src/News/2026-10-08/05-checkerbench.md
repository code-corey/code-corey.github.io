# CheckerBench: Can Long-Horizon Agents Synthesize Static-Analysis Checkers?（Agent 能否独立写出静态分析检查器）

> 📅 2026-10-08 | 🏷️ 前沿论文 | ⭐ HF upvotes 52（本期 HF 榜单最高）
> 🔗 原文：https://huggingface.co/papers/2610.07557

## 是什么

CheckerBench 是一个可执行的基准测试集，专门用来检验长程 Agent 能否从零开始、端到端地写出真正能用的静态分析检查器。它包含 300 个任务，全部来自 167 个真实仓库中的 297 个 CVE，覆盖 85 种 CWE 类型和 5 个语言生态。

## 🔍 小白解读

### 先说几个词

- **静态分析检查器**：不动手运行程序、只"读代码找毛病"的工具，就像体检中的验血报告——不切开身体，也能查出问题。
- **长程 Agent**：能连续执行一大串步骤的 AI 助手，不是一问一答，而是自己规划、动手、检查、重试，像接了个完整项目的员工。
- **CVE**：公开的安全漏洞编号档案库，每个已知漏洞都有一个类似身份证号的编号。
- **CWE**：漏洞的"分类学"，把各种软件缺陷归成不同类型，好比疾病按科室分类。
- **基准（Benchmark）**：一套标准考题，用来给不同模型打分排名，类似高考卷子。

### 这篇到底在说什么

现在测评 coding Agent 的考题大多是"给这段代码打个补丁"或者"看看这段代码有没有漏洞"。但业界还有一类更难的工作没人好好考过：从零写出一个能持续使用的检查工具。写这种工具要求 Agent 先读懂缺陷规范是什么、去翻看真实的代码仓库、再针对具体分析器框架实现逻辑，还要根据编译报错和分析结果反复修改。CheckerBench 就是为这类任务出的考卷：300 道题，每道题都附带真实漏洞代码和官方修复版本，Agent 写完检查器后可以直接跑起来验证效果。题目覆盖 85 种漏洞类型和 5 种编程语言生态，全部取材于真实 CVE，不是玩具题。论文指出，这种"从规范到可用工具"的端到端能力，正是现有基准的盲区。

### 这跟普通人有什么关系

你用的银行 App、购物网站，背后都靠这类检查工具守住安全底线。如果 AI 能自动造出更多、更贴合业务的检查器，软件出漏洞的概率就会下降，普通人的账户和数据也更安全。

## 为什么值得架构师关注

- 这是衡量「Agent 长程工程能力」的新标尺：补丁生成能力 ≠ 从规范设计出可用工具的能力，后者更接近真实团队里的高级工程师工作。
- 任务设计可直接借鉴：真实 CVE + 漏洞/修复配对 + 可执行验证，是搭建内部 Agent 评测集的现成模板，尤其适合安全工具链、代码质量平台的团队。
- 选型参考：如果你的场景是"让 Agent 产出可持续维护的工具"而非一次性补丁，现有 benchmark 分数可能高估了实际能力，建议用自己的类 CheckerBench 任务实测。

## 核心内容

- **任务规模与来源**：300 个任务，源自 167 个仓库的 297 个 CVE，覆盖 85 种 CWE、5 个语言生态，每题包含漏洞代码与对应修复。
- **考察的能力链**：理解缺陷规范 → 检查目标仓库 → 实现分析器特定逻辑 → 依据编译与分析反馈迭代，端到端闭环。
- **定位填补空白**：现有 coding-agent 基准多测补丁生成或漏洞检测，CheckerBench 首次系统化考核"从零写出能用的检查器"。
- **可执行性**：任务可实际运行验证，不是纯文本比对，评测结果更贴近真实工程。
