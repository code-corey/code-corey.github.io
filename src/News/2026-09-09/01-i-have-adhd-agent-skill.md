# I-have-ADHD: A skill to stop coding agents from burying the answer（I-have-ADHD：别让编码智能体把答案埋没）

> 📅 2026-09-08 | 🏷️ 工程 & Agent | ⭐ HN 298分/235评论
> 🔗 原文：https://github.com/ayghri/i-have-adhd
> 💬 HN 讨论：https://news.ycombinator.com/item?id=49610631

## 是什么

一个开源的轻量"技能"（skill）项目，专门治编码智能体的一个通病：干活之前先写一大篇分析、铺垫和方案对比，把真正的结论、改动点和风险埋在输出的最后甚至含糊带过。项目把这个毛病戏称为"ADHD 式输出"，用一份约束性技能文本让智能体改为结论先行。HN 上 298 分、235 条评论，说明这是普遍痛点。

## 🔍 小白解读

### 先说几个词

- **编码智能体（Coding Agent）**：能自己读代码、改代码、跑命令的 AI 助手，比如 Claude Code、Codex 这类，像个"会打字的实习工程师"。
- **技能（Skill）**：给智能体预装的一套"行为说明书"，通常就是一份结构化的指令文件，告诉它在特定场景下该怎么做、不该怎么做。
- **上下文工程（Context Engineering）**：精心设计喂给模型的指令和背景信息，让它输出更稳定——相当于给员工写一份好的岗位手册。
- **结论埋没（Burying the lede）**：新闻行业的说法，指把最重要的信息藏在长文末尾。智能体"小作文"就是典型：三段铺垫、五段分析，答案在第 40 行。
- **行为契约**：不改造模型本身，只用一段约定文本约束它的输出行为——便宜、即时、可版本管理。

### 这篇到底在说什么

你让 AI 帮你改一个 bug，它先给你上一堂课：分析架构、列举三种思路、讨论权衡取舍……等你读到第 30 段，才发现它到底改了哪一行。这个仓库做的事说穿了很简单：把"先说答案，再讲理由，没被问到别展开"写成一份技能，装进编码智能体里，让它改掉"小作文"习惯。打个比方，这就像给一个话痨实习生的工位上贴了张纸条："汇报先说结论，超过三句先打腹稿。"有趣的是 HN 上 235 条评论的热度——说明被智能体长输出折磨的人远比想象中多。而且这不是孤例：同期 GitHub 热榜上的 HERO-Anti-OverDefense（435 星）治的是另一个毛病——智能体"过度防御"（到处加检查、写防御代码收不住手）。两件事合起来看，社区正在形成一股潮流：**用轻量的行为契约给智能体立规矩，而不是等模型厂商慢慢改进**。

### 这跟普通人有什么关系

只要用过 AI 编程助手，就能立刻受益：答案前置意味着每次交互少翻几屏，省下的注意力和时间非常可观。对小团队来说，这还是零成本的改进——一段文本就能让所有人的 AI 助手变"清爽"。

## 为什么值得架构师关注

- **投入产出比极高的一类工程**：不改模型、不改代码，仅靠技能/指令层就能显著改善 Agent 输出质量，是"上下文工程"便宜见效的典型案例。
- **团队标准化素材**：输出格式规范（结论先行、变更点显式列出、风险单独标注）应进团队的 Agent 使用规范和代码评审清单，而不是靠每个人各自调教。
- **评测指标补充**：选型/评测 Agent 时，除了"能不能做对"，还应测"答案可定位性"——人要花多久找到关键信息。
- **趋势信号**：行为契约类项目集中走红（本项目 + HERO-Anti-OverDefense），说明当前模型的指令遵循仍需外挂约束，选型时要评估模型对长指令的服从度。

## 核心内容

- 仓库定位：一份可直接安装的 Agent 技能，目标是阻止编码智能体把答案埋在长篇输出里（结论先行）。
- 社区验证：HN 298 分 / 235 评论（2026-09-08），为当日 HN 工程类热帖之一，痛点共鸣强。
- 实现思路：prompt/技能级约束，无模型改造、无额外依赖，采用成本近乎为零。
- 同期印证：GitHub 热榜 HERO-Anti-OverDefense（435 星）用同类"粘贴即用契约"治理智能体过度防御——行为契约正在成为独立的工程手段。

## 行动建议

- 直接试用：把该技能装进团队的 Claude Code / Codex 等工作流，观察一周内评审效率变化，再决定是否纳入团队标准技能库。
- 顺手评估 HERO-Anti-OverDefense（gh.json 同期项目），把"结论先行"与"防止过度防御"两类契约组合使用。
- 在团队 Agent 规范中加入输出格式要求，并在代码评审 checklist 里加一条"变更点是否一眼可见"。
