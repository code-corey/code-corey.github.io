# Folkbench: AI API 中转站实测评测排行与切换工具（开源 AI API 中转站基准、排行与切换器）

> 📅 2026-10-14 | 🏷️ 值得研究的仓库 | ⭐ 843（慢热发现，Rust，2026-10-02 创建）
> 🔗 原文：https://github.com/Folkbench/folkbench

## 是什么

Folkbench 是一个用 Rust 写的开源工具，解决国内开发者大量依赖"AI API 中转站"（第三方转售 Claude/OpenAI 等模型 API 的服务）却无法判断服务质量的痛点：它实测各家中转站的真实可用率、延迟和价格，生成评测排行，并在 Claude Code / Codex 等编码工具场景下支持多供应商自动切换。创建于 2026-10-02，约两周累计 843 星。

## 🔍 小白解读

### 先说几个词

- **API 中转站**：把官方模型 API 转售/代理给国内用户的服务，价格常比官方便宜，但质量参差不齐。打个比方：官方是旗舰店，中转站是代购——便宜，但可能缺货、慢、甚至跑路。
- **可用率**：请求实际成功的比例。中转站的宣传再好听，可用率低就意味着你编码到一半 Agent 掉链子。
- **基准评测（Benchmark）**：用统一的测试方法给一堆服务打分排序，让"哪个好"从玄学变成数据。
- **故障切换（Failover）**：主服务商挂了自动换备用，就像家里断电自动点蜡烛——这里指的是 API 请求自动改道到备用中转站。

### 这篇到底在说什么

国内开发者用 Claude Code、Codex 这类 AI 编码工具，很多都走中转站。问题在于中转站市场极不透明：每家都说自己稳定便宜，实际用起来有的高峰期超时、有的偷偷降智（换成弱模型）、有的说跑路就跑路。Folkbench 的做法很"工程"：写一套统一的实测脚本，定期探测各家中转站的真实可用率、延迟、价格，把结果做成公开排行；再提供切换能力，当你正在用的中转站出问题时，编码工具可以自动换到表现更好的下一家。它不替你做决定，而是把选择权建立在公开可复现的数据上。两周 843 星说明这个痛点足够普遍。

### 这跟普通人有什么关系

如果你每月为中转站付费却经常遇到"转圈半天没反应"，这类实测数据能帮你避开坑；自动切换功能则让你写代码时少被供应商故障打断。

## 为什么值得架构师关注

- **供应商可靠性要靠数据不靠口碑**：这是"多供应商策略"在 LLM API 上的落地样板——评测维度（可用率/延迟/价格）就是你们应该为任何模型供应商建立的三张仪表盘。
- **成本与可靠性联动**：中转站价格差可达数倍，但可用率差一个 9 就可能让 Agent 长任务失败重试，综合成本反而更高——选型时建议用"有效单价（价格 ÷ 可用率）"来比较。
- **故障切换的工程位置**：切换逻辑应放在网关/代理层而不是客户端，Folkbench 的切换器实现可作为轻量级方案参考，企业级场景仍建议自建 LLM 网关。
- **合规提醒**：中转站模式本身存在条款与数据合规风险，企业生产环境需先过法务，勿仅因省钱引入。

## 核心内容

- 仓库：Folkbench/folkbench，Rust 实现，2026-10-02 创建，843 星，本期「慢热发现」（30 天窗口入选，非 7 天爆发）。
- 功能一：对 AI API 中转站做实测——可用率、延迟、价格三维度，输出公开排行。
- 功能二：面向 Claude Code / Codex 的切换工具，供应商异常时自动改道。
- 对标的真实痛点：中转站市场不透明、SLA 无保障，用户缺乏可复现的评测依据。

## 行动建议

- 团队内若使用中转站，参考 Folkbench 的评测维度自建探测脚本（简单 HTTP 探针 + 打分即可），每周出一份内部供应商健康报告。
- 把"有效单价 + 可用率"写进模型供应商选型标准，替代拍脑袋比价。
- 生产环境优先官方 API 或一级代理，中转站仅限开发/个人场景，并始终配置第二供应商。
