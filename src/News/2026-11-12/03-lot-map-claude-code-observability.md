# lot-map: A live map beside the chat（lot-map：聊天旁边的实时地图）

> 📅 2026-11-09 | 🏷️ 值得研究的仓库 | ⭐ 400（7 天爆发）
> 🔗 原文：https://github.com/alexeyw/lot-map

## 是什么

lot-map 是一个开源工具：在聊天窗口旁边放一张实时地图，把 Claude Code 正在做的事情全部亮出来——工具调用（tool calls）、模型步骤（model steps）、hooks、skills 和子智能体（subagents）在发生的瞬间点亮。纯本地运行，支持五种语言。2026-11-09 创建，7 天涨到 400 星，属于典型的「7 天爆发」项目。

## 🔍 小白解读

### 先说几个词

- **可观测性（observability）**：能随时看清一个系统「现在在干什么、为什么这么干」。就像厨房装了明档玻璃，客人能看到菜是怎么炒的，而不是只等一道菜端出来。
- **工具调用（tool calls）**：AI 干活时调用的各种「工具」，比如读文件、执行命令、搜索。相当于助理工作时用的电话、电脑和打印机。
- **hooks**：在特定动作发生时自动触发的「挂钩」，比如「每次保存文件前先跑一遍检查」。类似公司规定「盖章前必须登记」。
- **skills**：给智能体预先打包的技能包，让它按固定套路完成某类任务。像给新员工的「标准作业手册」。
- **子智能体（subagents）**：主智能体派出去的「分身」，各自处理子任务后向主智能体汇报。经理派活给组员。

### 这篇到底在说什么

用 AI 编码工具最让人心里没底的一点是：它到底在背后干了什么？lot-map 的答案是「给你一面玻璃墙」。它在 Claude Code 的聊天窗口旁边实时画一张地图，智能体每调用一个工具、每走一步、每触发一个挂钩、每派出一个子智能体，地图上对应的位置就亮起来。打个比方：以前 AI 干活像黑箱里的装修队，只听见响声不见人；现在装修队每人身上挂了个定位器，谁在敲墙、谁在走线一目了然。这个工具只在本地运行，数据不出你的电脑，还支持五种语言界面。7 天 400 星说明「看得见 AI 在干什么」是很多人的真实痛点。安装方式与支持的具体客户端，以仓库 README 为准。

### 这跟普通人有什么关系

对用 AI 工具写代码的人来说，它能帮你确认「AI 没有乱来」——改了哪些文件、跑了哪些命令都看得见。对小团队来说，这是一种低成本的信任基础设施：不用上复杂的审计系统，装个可视化地图就能对 AI 的行为有基本监督。数据只留在本地，敏感代码不用担心外泄给第三方看板。

## 为什么值得架构师关注

1. **智能体可观测性的落地形态**：团队推广 AI 编码工具的最大阻力往往是「不知道它在干嘛」。lot-map 给出了一个零成本、纯本地的可观测方案，可作为团队准入工具链的一部分。
2. **审计与合规入口**：可视化工具调用与子智能体行为，是后续做行为审计、异常检测（比如「智能体为什么执行了这条命令」）的第一步。
3. **架构启示**：它证明了可观测层可以独立于智能体本体存在（旁路观测、不侵入工作流），这个模式可以复制到企业内的其他智能体系统。
4. **评估成本低**：纯本地、可视化、无外部依赖，试点几乎零风险，适合作为「智能体治理」议题的破冰工具。

## 核心内容

- 功能：聊天窗口旁的实时地图，点亮显示工具调用、模型步骤、hooks、skills、子智能体活动
- 纯本地运行（Local only），支持五种语言
- TypeScript 实现；2026-11-09 创建，7 天获得 400 星
- 定位：智能体可观测性工具；安装与支持范围以仓库 README 为准

- 借此建立团队的智能体行为基线：哪些工具调用是正常的、哪些需要告警
