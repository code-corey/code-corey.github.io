# There is no posttraining data commons（后训练数据公共池并不存在：开放模型生态的真正瓶颈）

> 📅 2026-11-03（HN 热议；原文发布于 2026-10-15，作者 David Hall） | 🏷️ 前沿论文 | ⭐ HN 118分/27评论
> 🔗 原文：https://openathena.ai/blog/there-is-no-posttraining-data-commons/
> 💬 讨论：https://news.ycombinator.com/item?id=50352641

## 是什么

Open Athena 的一篇解释性长文（EXPLAINER），论证一个被低估的事实：**预训练时代人类「躺赢」了**——维基百科、开源代码、Stack Exchange、arXiv、古腾堡计划、Common Crawl（约 10PB）构成了免费的营养池，GPT-3 约六成训练数据源自 Common Crawl 衍生数据，初代 Llama 的数据配方几乎全部取自这个互联网公共池。但前沿重心已转向后训练（尤其是 agentic AI），而后训练需要的是「任务」而不是「文档」——**任务没有现成的公共池**。文章断言：没有持续访问公共数据池的渠道，真正开放的 LLM 就无法存在。

## 🔍 小白解读

### 先说几个词

- **预训练（pretraining）**：模型海量「阅读」互联网文本的阶段，像一个人读完了整座图书馆，学会语言和常识。
- **后训练（posttraining）**：阅读之后的「上岗培训」——用题目和反馈教会模型干活、听话、会用工具，强化学习是主流手段。
- **任务 vs 文档**：预训练吃的是现成文档（网页、书、代码）；后训练吃的是「任务」——有人想做一件事、尝试、环境反馈、调整、成败的完整过程。文档在网上到处都是，任务记录不是。
- **数据公共池（commons）**：大家共同维护、人人可用的公共资源，如维基百科和 Common Crawl，像公共图书馆。
- **开放模型 vs 开源权重**：只公开「大脑参数」（权重）≠ 开放——训练配方和数据来源不公开，别人无法完整复现，也无法持续迭代。

### 这篇到底在说什么

打个比方：开自助餐厅（预训练）时，街上正好有五十年攒下的免费食材市场，谁都能进货——这是 LLM 革命能爆发的运气。但现在行业卷到了「私教课」（后训练/agentic），私教课需要的不是食材，而是「学员练习册+教练反馈记录」，这种东西从来没有人免费公开过，每家都在自己屋里偷偷攒。文章进一步指出，「任务」比「文档」难公共化得多：人类真实的任务嵌在具体情境里，做一次就消失，像口述文化一样无法自动归档。结论很冷峻：权重开源只是开放生态的表象，缺了可持续的任务数据公共池，「真正开放」的大模型会逐渐变成少数巨头的附属品。

### 这跟普通人有什么关系

你用 AI 时的「帮我把这个表格整理成报告」背后，是厂商花大价钱造的练习题。开源模型如果后训练跟不上，免费模型和付费模型的差距会越拉越大——未来「免费」可能意味着「只够聊天，不够干活」。另外，你贡献给各平台的对话数据，正是在替厂商「攒私教教材」。

## 为什么值得架构师关注

- **开源模型评估维度修正**：评估开源/开放权重模型不能只看 benchmark 分数，要审其**后训练数据来源与授权**——这决定了可维护性与合规风险。
- **自建任务数据是隐性战略资产**：企业内部的 SOP、工单、评审记录若任务化沉淀，就是自己的「后训练私有池」；这是比买更多 GPU 更稀缺的资产。
- **RL 环境与评测集的成本曲线**：agentic 时代竞争焦点从算力转向高质量任务/环境构造，相关预算与人才规划应提前。
- **依赖闭源蒸馏的合规风险**：若产品能力依赖大厂模型的输出做训练（蒸馏），服务条款变化（如各家陆续收紧训练授权）会直接冲击迭代节奏——本期 HN 上 Gemini/Codex 训练条款争议正是同一背景。

## 核心内容

- 核心论点：预训练消费文档、后训练消费任务；文档有公共池（Common Crawl 约 10PB、维基/开源代码/Stack Exchange/arXiv/古腾堡），任务没有。
- 数据点（原文）：GPT-3 约 60% 训练数据源自 Common Crawl 衍生；初代 Llama 数据配方几乎全部取自互联网公共池；Cloudflare 报告过半爬虫流量已来自 AI。
- 机制分析：人类任务嵌于具体情境、一次性发生，天然难以像网页那样被爬取归档（作者称之为「口述文化」特征）。
- 推论：没有持续可访问的数据公共池，真正开放的 LLM 无法存在；权重开源 ≠ 开放。
- 传播信号：原文 10-15 发布，11-03 经 HN 推至 118 分，引发开源生态讨论。

## 行动建议

- 选型团队：把「后训练数据来源披露」列入开源模型评估 checklist；对只开源权重、不公开数据策略的项目谨慎承诺长期依赖。
- 平台团队：启动内部「任务数据资产化」——把高频 SOP 转成可复用的任务定义+验收标准，无论自训还是微调都会受益。
- 合规团队：复查对第三方模型输出的蒸馏使用是否与最新服务条款冲突。
