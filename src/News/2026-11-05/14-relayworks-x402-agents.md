# RelayWorks Recovery: resumable AI agent jobs with x402 USDC settlement（断点续跑的 AI Agent 任务 + x402 USDC 链上结算）

> 📅 2026-11-04 | 🏷️ Web3 & Crypto | ⭐ 47 星（**低于百星常规门槛，因解决的问题独特且模式样本价值高而破格入选**，7 天窗口）
> 🔗 原文：https://github.com/relayworkslab/relayworks-recovery
> 📎 主仓库：https://github.com/relayworkslab/relayworks

## 是什么

RelayWorks 系列仓库提出一个精准的痛点产品：**「你的 AI Agent 干到 70% 退出了，谁来收尾？」** RelayWorks Recovery 的答案是：从上次检查点（checkpoint）恢复任务，保留并**验证**已完成的部分，由「专家 Agent」只补完剩下的工作；用户**验收满意后**，才通过 x402 协议在 Solana 上用 USDC 付款。同一团队的主仓库还展示了纯 HTML/CSS/ES modules + Three.js 的产品站，集成 Solana 钱包登录与 x402 USDC 支付。

## 🔍 小白解读

### 先说几个词

- **Agent 断点续跑**：AI 干长任务（比如整理一千份文件）中途崩了，普通做法是从头再来；断点续跑像游戏存档，从上次的进度接着干。
- **检查点（checkpoint）**：任务进行到关键节点时保存的「进度快照」，包含已完成的工作和中间状态。
- **x402**：基于 HTTP 402 状态码（「需要付费」）的微支付协议——访问一个接口时自动附带小额链上付款，机器对机器付费的标准化尝试。
- **USDC**：锚定美元的合规稳定币，链上转账即时到账，适合小额、高频的机器间结算。
- **验收后付费（pay on acceptance）**：先看结果、满意再付钱——把传统外包行业的验收逻辑搬进了 Agent 服务市场。

### 这篇到底在说什么

打个比方：你雇了个小时工（AI Agent）整理车库，干到七成突然辞职不干了（Agent 中途退出/超时/报错）。以前的损失是全部重来；RelayWorks 的方案是：先给车库拍照存档（检查点），小时工走后请另一位师傅来，先核对哪些活干合格了（验证已完成部分），只补干剩下的三成，你最后验收满意才扫码付钱（x402 + USDC 链上结算）。这个组合——可恢复的任务执行 + 验证式接手 + 结果驱动的微支付——把「AI Agent 服务」做成了可以像外包一样计价与验收的市场，而链上结算解决了「机器对机器、小额、免信任」的付款难题。

### 这跟普通人有什么关系

委托 AI 干活的人以后可以少花冤枉钱：干一半崩了的任务不必全款重付，「验收后付费」会逐渐成为 Agent 服务的主流体验。对自由职业者/服务提供方，Agent 完成的标准化工作会以微支付方式结算——一部分「活儿」的定价单位正在从「天」变成「次」甚至「厘」。

## 为什么值得架构师关注

- **结算模式创新值得拆解**：x402（HTTP 原生微支付）+ USDC（稳定币）+ 验收后付款 = 「免信任的 Agent 服务市场」三件套。任何「多 Agent 协作/Agent 市场」方向的架构设计都应评估这套组合的适用性。
- **可恢复执行是通用工程模式**：检查点 + 已完成部分验证 + 增量接手，与区块链无关，可直接移植到企业内部长任务的 Agent 编排中——这是本仓库对纯 Web2 团队的最大价值。
- **验证环节是信任锚点**：「Completed work is kept and verified」意味着需要一个独立于执行方的验证器——设计 Agent 流水线时，执行与验收分离的原则在这里得到具象化。
- **早期项目风险**：47 星、上线一天，产品与协议均未经验证；把它当作**模式参考实现**而非生产依赖。

## 核心内容

- 痛点定义：AI Agent 任务在约 70% 进度处失败/退出，重启即全损。
- 方案三步：从最后检查点恢复 → 保留并验证已完成工作 → 专家 Agent 只补完剩余部分。
- 结算设计：用户验收后通过 x402 协议在 Solana 上以 USDC 付款（pay-on-acceptance）。
- 实现风格：主站为纯 HTML/CSS/ES modules + Three.js，Solana 钱包登录 + x402 USDC 支付集成（主仓库描述）。
- 仓库状态：recovery 仓库创建于 11-04，47 星（7 天窗口；低于百星门槛，独特性问题破格入选）。
