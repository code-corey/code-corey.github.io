# Grandet: Find the cheapest API for any model（Grandet：给 AI Agent 自动找最便宜模型 API 的比价工具）

> 📅 2026-10-29 | 🏷️ 值得研究的仓库 | ⭐ 940（慢热发现：30 天窗口，2026-10-05 创建）
> 🔗 原文：https://github.com/hanzohanzhe/Grandet

## 是什么

GitHub 上由中文开发者维护的开源项目 Grandet：一套"给 Agent 用的模型 API 比价工具"，包含 Grandet Skill 和一个匿名 MCP 服务器，价格数据来自 grandet.ai 收录的 1800+ 官方渠道、推理服务商和中转渠道的挂牌价格。Agent 调用它就能回答"同一个模型，现在哪家最便宜"，并把请求指向更省钱的通道。一个月内积累约 940 星，属于渐进爬坡的慢热型项目。

## 🔍 小白解读

### 先说几个词

- **MCP（Model Context Protocol，模型上下文协议）**：一个开放标准，让 AI 模型能以统一方式连接外部工具和数据源。打个比方：以前每件电器一种插头，MCP 相当于统一了插座标准。
- **Skill（技能包）**：预置好的能力模块，Agent 装上后不用每次重新教，就能直接执行特定任务，像给员工配好的标准作业手册。
- **推理服务商（Inference Provider）**：不只模型原厂，还有很多云公司代为运行开源模型卖 API，同一模型价格可以差数倍。
- **中转/代理渠道（Relay）**：转卖模型 API 的二级渠道，价格更低但稳定性和合规性参差不齐。
- **挂牌价（Listed Price）**：服务商公开标出的价格，Grandet 只做价格发现，不碰你的请求内容。

### 这篇到底在说什么

打个比方：模型 API 市场像一个巨大的机票市场——同一条航线（同一个模型），不同代理商报价天差地别，而且天天变。Grandet 做的事，就是给你的 AI 助手装了一个"机票比价引擎"：它自己就是 Agent 的一部分，Agent 在部署或调用模型前，先问一句"哪个渠道最便宜"，然后照着最省钱的方案走。项目的两个关键设计值得注意：一是以匿名 MCP 服务的形态提供，比价请求不暴露调用者身份；二是数据基于挂牌价而非黑箱估算，可核对。940 星的增长节奏说明"模型采购成本优化"已经是一个普遍痛点，而不是少数极客的需求。

### 这跟普通人有什么关系

如果你在用各类 AI 应用，背后的公司在比价，你的订阅费就有下降空间；如果你自己折腾 API 或自部署 Agent，这类工具能直接降低每月账单。对"用哪家模型服务"这类决策，它也把原本靠道听途说的选择变成了可查证的数据。

## 为什么值得架构师关注

- **成本治理工具化**：LLM 成本优化的第一步是价格发现。Grandet 把"比价"变成了可编程接口，可以接进内部的模型网关/路由层，做成本感知路由（cost-aware routing）。
- **多供应商策略的基础设施**：1800+ 渠道的价格数据支撑"主通道+备通道"的容灾设计，防止单一服务商涨价或限流时被动。
- **合规提醒**：中转渠道价格虽低，但数据出境、SLA、计费审计都有风险——比价数据可以参考，生产流量走中转前必须过法务与稳定性评估。
- **匿名 MCP 的取舍**：匿名查询保护了业务隐私，但也意味着没有 SLA 承诺，适合作为决策数据源而非关键路径依赖。

## 核心内容

- 项目构成：Grandet Skill + 匿名 MCP 服务器，语言 JavaScript，GitHub 约 940 星（创建于 2026-10-05，30 天窗口慢热增长）。
- 数据覆盖：grandet.ai 收录的 1800+ 官方渠道、推理服务商与中转渠道的挂牌价格。
- 设计取向：价格来自公开挂牌价，查询匿名化，面向"Agent 自助比价"场景而非人工比价网站。
- 与同期 HN 上"5 个 abliterated DeepSeek 推理供应商"等话题呼应：同一模型多渠道供应已成常态，比价需求真实存在。

## 行动建议

- 值得评估试用：先用它做一次内部模型采购价格的盘点，对比当前主力通道是否有 30%+ 的价差空间。
- 若引入，建议只把挂牌价数据接进成本看板与路由决策，生产流量仍走签约渠道；中转渠道列入"降本备选"而非默认。
- 关注其价格数据的更新频率与覆盖率是否匹配你实际使用的模型清单，再决定是否长期依赖。
