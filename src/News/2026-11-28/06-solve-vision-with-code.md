# Solve Vision with Code: Coding Agents Are Stronger Visual Reasoners Than Video Models（用代码解决视觉问题：编码 agent 是比视频模型更强的视觉推理器）

> 📅 2026-11-28 | 🏷️ 前沿论文 | ⭐ HF upvotes 59
> 🔗 原文：https://huggingface.co/papers/2611.34813

## 是什么

一篇挑战技术路线默认答案的对照实验论文。当前范式把视频生成模型当作"视觉推理器"评估：给首帧和一句自然语言指令，让模型直接生成"任务被完成"的视频，理由是推理"原生发生在视觉介质里"。这篇论文用完全相同的任务、输入与输出规范，测试了符号路线的对立面——编码 agent 用写代码的方式解决同一批视觉任务——结果编码 agent 是更强的视觉推理器。

## 🔍 小白解读

### 先说几个词

- **视觉推理**：不只是"看清图里有什么"，而是"推演图里会发生什么、该怎么操作"——比如判断积木塔倒向哪边、机器人该怎么绕过障碍。
- **视频生成模型**：输入图片和文字、输出一段视频的模型。新范式认为它生成视频的过程本身就是一种"思考"。
- **编码 agent**：会写代码、调用工具的 AI。面对同一个视觉任务，它不是"演"出结果，而是写下一段模拟/计算代码，算出结果。
- **符号路线**：与"视觉原生"相对——把问题翻译成代码、逻辑、方程来解。像物理题不用脑子想象、而是列公式硬算。
- **对照实验**：两种方法吃完全相同的"考卷"，排除题目难易差异，公平比出高低。

### 这篇到底在说什么

打个比方：要回答"这个花瓶从桌上掉下去会不会碎"，一种思路是让 AI 在脑内"放电影"——想象整个下落过程，直接给你放一遍；另一种思路是让 AI 写一道物理公式算冲击力。过去业界的直觉是第一种更"高级"——推理直接发生在画面里，多原生啊。这篇论文做的事很朴素但很扎心：把同一批"考卷"发给两种 AI，第一种交的视频作业、第二种交的代码作业，用同一套标准批卷——结果写代码的"解题生"稳定答得更好。这意味着"生成即推理"的范式优势可能是一种未经检验的信仰：看起来直观，不代表推理更可靠。代码路线可检查、可复算、可定位错误，这些性质在需要"答案正确"而非"过程好看"的场景里价值巨大。

### 这跟普通人有什么关系

未来你用的 AI 产品遇到"看图办事"类任务（比如让 AI 看着房间照片规划打扫路线），背后走哪条技术路线，直接决定它是"大概看起来对"还是"真的对"。这篇论文支持把关键任务交给"会算的 AI"而不是"会演的 AI"。

## 为什么值得架构师关注

- **路线选型的实证依据**：凡是"视觉输入 → 物理操作/空间决策"类需求（机器人、GUI 自动化、游戏 agent），本文提供了反对"盲目上视频生成模型"的对照证据——工具/代码路线在同等条件下更可靠。
- **成本结构差异巨大**：视频生成按帧算力计价且结果不可复验；代码推理一次生成、可单测、可调试。关键路径上的可验证性应优先于直观性。
- **混合架构启示**：合理组合可能是"视频模型负责想象与候选生成，代码负责精确验证与执行"——设计 agent 管线时把两者放在不同角色而非二选一。
- **评测设计警示**：本文也提示现有"视频模型当推理器"的评测范式本身需要重新审视。

## 核心内容

- 实验设计：同一批视觉推理任务、相同输入与输出规范，分别交给视频生成模型（原生视觉路线）与编码 agent（符号代码路线）。
- 核心结论：编码 agent 是更强的视觉推理器——符号路线在同等条件下胜出。
- 论证意义：'推理原生发生在视觉介质中'这一范式优势主张此前未被对照检验，本文补上了这个实验。
- 热度佐证：HF upvotes 59，居本期论文前列，且属于"新范式质疑"类而非刷 SOTA 类。

## 行动建议

- 具身智能/GUI 自动化/空间推演类项目：优先验证"感知模型 + 代码推理"管线，把视频生成模型降级为创意/预演组件。
- 多模态选型评审中，把"该路线的结果可否复验"列为与准确率同级的评估维度。
- 依赖视频生成做决策的存量系统：抽样回放验证其决策正确率，对照本论文结论评估风险。
