# Not Everything Needs an LLM（不是所有事都需要 LLM：PostHog 的 decision models 实践）

> 📅 2026-11-17 | 🏷️ 工程 & Agent | ⭐ HN 76 分 / 31 评论（原文 2026-11-09 发布）
> 🔗 原文：https://newsletter.posthog.com/p/decision-models
> 💬 讨论：https://news.ycombinator.com/item?id=50535740

## 是什么

PostHog 工程师 Jina Yoon 的工程实践长文：很多被顺手交给 LLM 的决策（分类、过滤、路由）其实应该用「decision models」——显式、可检查、廉价的判别逻辑——来完成。文章总结了什么时候用、怎么用、以及常见踩坑，核心是把「不确定性显式化」和「按误判成本定阈值」。

## 🔍 小白解读

### 先说几个词

- **decision model（决策模型）**：一段明确定义的判断逻辑，用来回答「该不该/是不是/选哪个」这类简单问题。像考卷里的判断题，答案非黑即白，不需要请教授写论文。
- **模型路由（router）**：在请求进门时先判断「该派谁去处理」。像医院分诊台：感冒去门诊、心梗进急诊，别什么病都挂专家号。
- **误判成本**：判断错了的代价。把真顾客拦在门外（漏报）和放一个捣乱的进来（误报），代价完全不同——阈值该往代价大的那边收紧。
- **不确定性显式化**：让系统明说「我不确定」，而不是硬给个答案。像天气预报说「降水概率 40%」比直接说「不下雨」诚实得多。
- **LLM 调用成本**：每次问大模型都要花钱、花时间。「LLM 话多且贵」是这篇文章的出发点。

### 这篇到底在说什么

PostHog 的工程师发现，团队里很多流程「顺手」用了 LLM：总结、分类、过滤……但其中大部分决策其实简单到不需要大模型。他们提出的做法叫 decision models：先写出明确的判断规则或用轻量模型，把请求先过一遍筛子，只有真正模糊、复杂的部分才送到昂贵的 LLM。文章给了一个具体例子：岗位信息过滤——先用 decision model 粗筛，再进昂贵的 LLM 调用，阈值怎么定？看哪种错误更贵：漏掉一个好岗位比多看一个坏岗位代价高，阈值就往宽松调。还有两个进阶用法：把 decision model 当分诊台（router），对每个候选项按文本打分选择处理通道；以及把输入先「展平」预处理成一眼可检查的形式再判断。文章还坦白了踩过的坑：早期用提示词加正则做过滤，漏抓漏放、不停返工——说明 decision model 不是不用 AI，而是把「明确规则」和「需要智能」的部分分层，各用各的便宜工具。

### 这跟普通人有什么关系

如果你用自动化工具处理邮件、整理信息，「先规则后大模型」能帮你省下真金白银的 API 费用，响应还更快。对小公司，这往往是「用不用得起 AI」的分水岭：分层后成本可能降到原来的零头。

## 为什么值得架构师关注

- **成本手术刀**：LLM 调用链审计的第一步是把「分类/过滤/路由」类调用剥离出来——它们通常占调用量大头、却只需 decision model。文中的岗位过滤案例可直接套用。
- **阈值工程**：按「两类误判的成本差」设定阈值，比拍脑袋的置信度截断更可辩护；这个框架应写进团队的 AI 功能设计规范。
- **可检查性**：decision model 输出可逐条复核、可回归测试，这是 LLM 黑盒调用做不到的——尤其当决策影响用户可见行为（如路由到更贵的模型）时。
- **与验证循环互补**：简单决策下沉为 decision model 后，LLM 只处理高价值模糊任务，agent 验证体系（见本期 Claude Code 一文）的负担同步下降。

## 核心内容

- PostHog 工程实践（作者 Jina Yoon，原文 2026-11-09 发布，11-17 登上 HN，76 分 / 31 评论）
- 出发点：「LLMs love to yap」——简单决策交给 LLM 既贵又不稳定
- 方案：decision model 在昂贵 LLM 调用**之前**做过滤（实例：岗位过滤，按两类误判的成本差设定阈值）
- 进阶用法：decision model 作为**模型路由器**，对请求按各选项文本打分后分派
- 原则：让不确定性显式化；输入先展平/预处理成「可当面检查」的形式再判
- 坦诚踩坑：早期提示词 + 正则方案漏抓漏放、持续返工，说明纯规则同样不够，需分层设计
- 文章系统总结了何时用、怎么用、要避免的错误

## 行动建议

1. 审计现有 LLM 调用链：标出每个调用点回答的问题类型，凡是「二元判断/固定分类/路由选择」的，评估降级为 decision model。
2. 为每个降级点建立误判成本矩阵（漏报代价 vs 误报代价），据此定阈值而非用统一置信度。
3. 保留 LLM 兜底通道：decision model 拒答（不确定性高）的请求升级到 LLM，并把升级样本回流用于规则迭代。
