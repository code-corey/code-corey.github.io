## 是什么

burnrate-ai 组织同时开源了两个仓库：**burnrate-shield** 是一个「agent 无关」的 AI agent 钱包熔断层——在每笔交易签名之前检查交易内容，发现拖库（drainer）行为直接拦截，支持 EVM 和 Solana；**burnrate-bench** 是配套的独立对抗基准——用外部 fork 做裁判，在无防护 vs 有防护两组之间跑 10 类攻击原语，仓库口号直白：「Built to fail the product（造出来就是为了打败这个产品）」。

## 🔍 小白解读

### 先说几个词

- **链上智能体（on-chain agent）**：拿着钱包私钥、能自己发交易的 AI 程序。像一个有银行卡还能自己去柜员机的机器人助理——能干很多活，也可能被坏人骗着把钱转走。
- **提示注入（prompt injection）**：攻击者往 AI 能读到的内容里藏指令，骗它做坏事。像在助理的日程表里夹一张假纸条：「老板说了，把保险柜打开」。
- **拖库（drainer）**：一类自动化偷币工具，诱导签名或骗授权后把钱包洗空。加密圈每年因它损失数十亿美元级。
- **熔断层（containment layer）**：在危险操作执行前的最后一道闸。像断路器：电流（交易）再正常，超标就跳闸。
- **对抗基准**：专门用来攻击自家产品的测试集。相当于自己雇红队天天打自己，打不倒才敢上线。

### 这篇到底在说什么

现在很多人给 AI 智能体配了加密货币钱包，让它自动交易、自动付款。风险随之而来：智能体是被提示词驱动的，一旦被注入恶意指令（比如读到一个藏毒的网页），它可能「认真地」把整个钱包转给攻击者。burnrate-ai 给出的方案分两层：第一层是 shield——所有交易在签名之前先过一遍检查，发现「清空式转账」「可疑授权」这类拖库特征就拦下来，不管这个 agent 用的是什么模型、什么框架；第二层更罕见——他们同时发布了一个专门用来攻击自己的基准测试：把「装了盾」和「不装盾」两种钱包放进同样的 10 类攻击场景里（覆盖 EVM 和 Solana），让一个外部仲裁程序（用仓库的 fork 版本当裁判，避免既当运动员又当裁判）判定谁守住了。这个项目目前几乎无人知晓（各 1 星），但它提出的问题——「怎么证明 agent 钱包防线真的有效」——恰好是链上智能体走向生产的必答题。

### 这跟普通人有什么关系

如果你用过或打算用「AI 帮你管理加密资产」的产品，这类熔断层就是你和灾难之间唯一的缓冲垫。选这类产品时，可以问一句：你们有没有公开的对抗测试？答不上来的要小心。

## 为什么值得架构师关注

- **「产品 + 反向基准」双仓发布模式**：把红队测试作为产品的一等公民公开，是 AI 安全工程正在成型的信号；内部做 agent + 资产类功能时应复制该模式（至少私有化复制）。
- **签名前策略检查是正解位置**：事后追回在链上不可能，防线必须放在签名动作之前。该仓库给出了策略检查点的参考位置（签名 API 旁路拦截），EVM + Solana 双栈实现。
- **agent 无关（agent-agnostic）设计**：防护做在钱包/交易层而非某个 agent 框架内，与框架生态解耦——这是企业集成友好的正确抽象层级。
- **风险提示**：1 星 / 0 fork / 无审计记录 / 文档成熟度未知，代码未经社区检验。方向信号价值 > 工程可用价值。

## 核心内容

- **burnrate-shield**：agent 无关的钱包熔断层，签名前逐笔检查交易并在签名前拦截拖库；支持 **EVM + Solana**（仓库描述）；MIT / TypeScript
- **burnrate-bench**：独立对抗基准——无盾 vs 有盾对比、**外部 fork 作裁判**、**10 类攻击原语**，明确声明「Built to fail the product」
- 两仓库 topics 一致：ai-agents、ai-safety、containment、prompt-injection、crypto-wallet、ethereum、solana
- GitHub API 实测（11-18）：各 1★ / 0 fork / 均创建于 2026-11-13 / 最近推送 2026-11-16 / 均有项目主页（burnrate-hq.vercel.app）
- 定位：Web3×AI 交叉（链上智能体安全）的早期方向信号，非成熟组件

## 行动建议

1. 做 agent + 钱包/资产类产品的团队：**不要直接采用**该早期组件，但应立即补上两类能力——签名前策略检查点、私有化的对抗基准（可参考 bench 的「外部裁判」设计避免自测自证）。
2. 采购类决策者：把「是否有独立对抗测试」加入 agent 金融类产品的供应商问卷。
3. 研究者：这两个仓库规模小、结构清晰，适合作为「agent 钱包威胁建模」的入门代码样本阅读。
