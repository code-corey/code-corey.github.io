# Pandex – Official European Law for AI Agents, over MCP（把欧盟 AI 法律装进 MCP 的 Agent 合规层）

> 📅 2026-11-21 | 🏷️ 工程 & Agent | ⭐ HN 139 分/33 评论
> 🔗 原文：<https://www.pandex.io>
> 💬 讨论：<https://news.ycombinator.com/item?id=50593481>

## 是什么

Pandex 定位为「AI Agent 的欧洲官方法律合规层」：通过 MCP（Model Context Protocol）把欧洲 AI 相关法规要求接入 Agent 工作流，让 Agent 在欧盟语境下运行时自带合规约束。项目上线即登上 HN 首页（139 分/33 评论）。

## 🔍 小白解读

### 先说几个词

- **MCP（Model Context Protocol）**：让 AI 模型以标准方式调用外部工具与数据源的「USB-C 接口」，Agent 通过它连接数据库、API、各种服务。
- **AI Agent**：能自己拆解任务、调用工具、连续执行多步操作的 AI 程序，比如自动处理工单、自动分析报表的智能体。
- **欧盟 AI 法规**：欧盟按风险等级对 AI 系统提出透明度、人类监督等要求的法律框架（如 AI Act），违规可能面临高额罚款。
- **合规（Compliance）**：让软件行为符合法律法规的过程，通常靠审计日志、权限控制、内容约束来实现。

### 这篇到底在说什么

打个比方：AI Agent 像一个能干的助理，但欧盟法律要求这个助理工作时遵守一堆规矩——不能误导用户、要保护隐私、高风险场景要有人监督。Pandex 想做的，是把这些法律要求做成 Agent 可以「即插即用」的能力：Agent 通过 MCP 调用 Pandex，就像助理随身带着一本欧盟法律手册和合规检查清单，干活时随时对照。对企业来说，这省去了自己把法规逐条翻译成工程约束的成本；对 Agent 开发者来说，接上合规层后更容易向客户证明「我的 Agent 守规矩」。当然，HN 社区对此有争议——法律条文能否被这样结构化、出了问题责任算谁的，这些都是开放问题，原帖讨论值得细读。

### 这跟普通人有什么关系

如果你在欧洲使用 AI 服务，这类合规层意味着你面对的 Agent 更可能被明确告知「我是 AI」「我不能做什么」；对小公司而言，它降低了出海欧盟时自建合规体系的门槛。

## 为什么值得架构师关注

- **选型影响**：面向欧盟用户的 Agent 产品绕不开 AI Act 合规，「法规即服务（Law-as-a-Service via MCP）」可能成为合规技术栈的独立一层，值得纳入架构评审清单。
- **集成成本**：经 MCP 接入意味着改动集中在工具层，不需要重写 Agent 编排逻辑；评估时重点测它对延迟与工具调用预算的影响。
- **风险点**：把合规外包给第三方，必须审查其法条覆盖范围、更新时效与责任条款；HN 讨论中已有争议，POC 阶段应让法务参与验证其输出。
