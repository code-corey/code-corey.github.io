# Fast-Anything: Don't rewrite it in Rust. Rewrite the 5% that's slow（别全重写成 Rust，只重写那慢的 5%）

> 📅 2026-11-21 | 🏷️ 值得研究的仓库 | ⭐ 1.9k（7 天窗口）| 语言：Rust
> 🔗 仓库：<https://github.com/EL4CTEO/fast-anything>
> 💬 HN 讨论：<https://news.ycombinator.com/item?id=50596155>（177 分/148 评论）

## 是什么

Fast-Anything 是一个上线 7 天就拿到约 1900 星的 Rust 工具链，主张「不要把整个项目重写成 Rust，只重写那慢的 5%」：先对 Python/Node/Ruby 应用做性能画像（profiling）找出热点函数，交给你的编码 Agent 移植成 Rust，并证明移植后的函数行为与原来一致。

## 🔍 小白解读

### 先说几个词

- **性能画像（Profiling）**：给程序做「体检」，记录每个函数花了多少时间，找出拖慢整体的少数热点。
- **热点函数**：吃掉大部分运行时间的少数代码——通常 5% 的代码占了 95% 的耗时。
- **Rust**：以速度和内存安全著称的系统级语言，但开发效率低于 Python/Node，全量重写成本极高。
- **编码 Agent**：能读代码、改代码、跑测试的 AI 编程助手。
- **行为一致性验证**：用相同输入对比新旧实现的输出，确保「提速但不改结果」。

### 这篇到底在说什么

「用 Rust 重写」是程序员圈的老梗：很多团队为了性能把 Python 项目全部重写成 Rust，结果花了一年，性能只提升一点，bug 倒添了一堆。打个比方，这就像嫌家里某间房冬天冷，正确做法是给那间房加装暖气，而不是把整栋房子推倒重盖。Fast-Anything 把这件事工具化了：第一步自动给程序做「体检」找出最耗时的几个函数；第二步让 AI 编码 Agent 把这几个函数翻译成 Rust；第三步验证新函数和旧函数对同样的输入给出同样的输出。三步走完，你的 Python 应用保住了开发效率，又拿到了关键路径的系统级性能。仓库描述特别强调「prove they behave the same」——把验证环节做进流程，这是它比普通「AI 重写脚本」更工程化的地方，也是 HN 讨论（177 分/148 评论）的焦点所在。

### 这跟普通人有什么关系

如果你公司的老系统越来越慢、又没预算整体重构，这种「精准手术」思路能花小钱办大事；对开发者来说，「AI 移植热点代码 + 自动验证」正在变成一项新技能。

## 为什么值得架构师关注

- **性能工程策略**：为「遗留系统提速」提供了可复制模式——profiling 定位 + Agent 移植 + 等价性验证，比全量重写风险低一个量级。
- **Agent 工作流范式**：把 AI 编码 Agent 约束在「单函数移植 + 证明等价」的窄任务里，是降低 AI 改码风险的良好范式，可迁移到团队自己的重构流程。
- **成本视角**：只在热点引入 Rust（FFI 边界），避免双语言全栈维护，团队只需极少数人懂 Rust。
