# unlazy（AI Agent 反偷懒技能：Depth Tree 方法）

> 📅 2026-08-09 创建（约 25 天 ⭐ 2,981） | 🏷️ 🧰 值得研究的仓库 | ⭐ 2,981（7 天 + 30 天双窗口热门榜首）
> 🔗 原文：https://github.com/Leonxlnx/unlazy
> 💬 语言：JavaScript

## 是什么

一个针对 AI agent"偷懒"问题的技能/方法库。核心是 **Depth Tree（深度树）方法**：把任务沿深度方向拆分 N 层，并让**每一个叶子节点都获得与整个任务相同的时间预算**，使实际投入的算力随深度倍增。方法建立在 2025-2026 年关于模型 laziness（偷懒）、underthinking（思考不足）与 premature completion（提前收工）的研究之上。

## 🔍 小白解读

### 先说几个词

- **偷懒（laziness）**：AI 的真实毛病——让它改 100 个文件，它改 3 个就说「已完成」；遇到难题浅尝辄止草草收工。根源是训练时学会了「少花力气」。
- **思考不足 / 提前收工**：偷懒的两个学术马甲——没想清楚就回答（underthinking）、没做完就宣布完成（premature completion）。
- **任务树 / 叶子节点**：把大任务拆成一棵树，最末端的每个小任务就是叶子节点。本文方法：每个小任务都享有「整个大任务」同等的时间预算。
- **时间预算**：允许 AI 花在思考上的算力额度。预算越多，AI 思考越深。
- **低容错场景**：错一点点就出大事的任务，如财务计算、安全分析、生产环境改代码。

### 这篇到底在说什么

大家都发现 AI 会偷懒：活干到八成就宣布完工。这个开源项目给了一个硬核处方：把大任务拆成一棵任务树，然后规定——每个最末端的小任务，都享有和原来整个大任务一样多的思考时间。相当于原来只给一次「深度思考」的预算，现在拆成十份、每份都是全额。代价是算力成倍地烧，换的是把活干彻底。25 天近 3000 星，说明被 AI 偷懒坑过的人实在太多。

### 这跟普通人有什么关系

直接可用的启示：重要任务别用「帮我把全部改完」这种一句话指令，拆成清单、每项都要求完整交付，AI 的完成质量立刻不同（这个工具把这个思路自动化了）。另一个启示：AI 偷懒不是你的错觉，是行业公认难题，正在被系统性解决——未来几个月你的 AI 助手会越来越「不摸鱼」。

## 为什么值得架构师关注

Agent "偷懒"是生产环境最常见也最难量化的问题：任务拆解后子任务草草收场、长任务后段质量断崖、report 写得漂亮但验证缺失。unlazy 的价值在于把一个"玄学体验问题"转成**可工程化的预算分配策略**——时间预算跟着任务树结构走，而不是平均摊派。对于任何在跑长链路 agent（编码、研究、运维巡检）的团队，这是直接作用于输出质量的杠杆，且不需要换模型。

## 核心内容

- **Depth Tree 方法**：任务递归拆分为 N 层深度的树；关键设计是每个叶子节点继承"整个原始任务"的时间预算，从根本上消除"子任务不配得到深思考"的隐性配额。
- **算力随深度倍增**：与传统的扁平任务拆分相比，投入随树深指数级放大，用预算换彻底性——适合高价值、低容错的场景。
- **有研究根基**：明确对接 2025-2026 年模型偷懒/思考不足/提前完成三个研究方向，不是凭经验的 prompt 集合。
- **增长信号强**：约 25 天 2,981⭐，为今日 GitHub 双窗口榜单第一，社区验证了问题普遍性。

## 行动建议

- 选一个当前偷懒最严重的 agent 工作流（通常是多步编码或深度调研类），用 Depth Tree 重排其任务预算，A/B 对比完成质量与 token 消耗。
- 注意成本侧：预算随深度倍增意味着费用同步上升，建议只在"错误代价 >> 算力成本"的任务上开启全量深度。
- 与自家评测集联动：偷懒往往表现为验证步骤缺失，可给 agent 加"叶子节点必须自带验证输出"的硬约束来量化收益。
