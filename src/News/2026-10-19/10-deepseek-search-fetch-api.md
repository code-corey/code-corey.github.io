# DeepSeek search and fetch – $0.75 per 1000 successful requests（DeepSeek 开放搜索抓取 API：成功请求 $0.75/千次）

> 📅 2026-10-19 | 🏷️ 国内生态 | ⭐ HN 534分/256评论
> 🔗 原文：https://api-docs.deepseek.com/guides/search/
> 💬 HN 讨论：https://news.ycombinator.com/item?id=50138531

## 是什么

DeepSeek 官方 API 文档上线 search & fetch 指南：开发者的应用/Agent 可以直接调用 DeepSeek 的联网搜索与网页抓取能力，定价按「成功请求」计——每 1000 次成功请求 0.75 美元。这是继模型本体之后，DeepSeek 在 Agent 基础设施上的关键补件。HN 534 分、256 条评论，是今日 AI 圈全站热度第一的话题。

## 🔍 小白解读

### 先说几个词

- **API**：程序调用某项服务的标准接口，像餐厅的点菜窗口——不用进厨房，递单子就行。
- **Search & fetch**：搜索（找到相关网页）+ 抓取（取回网页正文）两步，是 AI「查资料」的完整动作。
- **按成功请求计费**：只对真正拿到结果的调用收钱，失败的请求不计费。
- **RAG（检索增强生成）**：先查资料再让大模型作答的技术，答案的可靠性取决于检索层质量。

### 这篇到底在说什么

以前你想做一个「会查资料」的 AI 助手，要自己拼积木：接一个搜索服务商拿结果、再接抓取工具取正文、还要自己清洗内容——链路长、单价高、三方都不稳定。DeepSeek 现在把「搜索 + 抓网页」直接做进自家 API：模型查资料不用出门，一行配置就行，价格明码标价——一千次成功查询 0.75 美元，比国际主流搜索数据服务的常见单价低一个量级。打个比方：以前自己跑菜市场买菜再回家做饭，现在餐厅直接送成品半菜上门。HN 上 500 多分，全球开发者都在算这笔账：Agent 的检索层，要不要换个更便宜的供应商。

### 这跟普通人有什么关系

用 DeepSeek 做客服、知识库、助手的团队，产品会「更会查资料」且成本更低；价格战继续打下去，各类 AI 助手的订阅费和使用成本都会被压低。

## 为什么值得架构师关注

直接影响 Agent 栈的检索选型：自建链路（SERP API + 抓取 + 清洗 + 运维）与一行内置工具之间的成本差需要重算——高并发、低价值密度的检索场景（客服 FAQ、舆情扫描）尤其值得对比。评估维度四项：搜索质量（中英文相关性、时效性）、正文抓取质量（对 RAG 命中率的影响）、成本模型（成功请求计费对失败重试的友好度）、可移植性（检索能力与 DeepSeek 模型是否深度耦合，换模型时能否带走）。两个风险别忽略：与单一厂商的耦合加深——检索层换成厂商内置后，迁移成本同步上升；以及数据合规——检索请求内容出境与留存政策需要法务过目。

## 行动建议

值得评估：若检索链路自建或使用高价搜索服务，用真实查询集做一次 POC——对比命中率、正文质量、单千次综合成本；在架构上保留检索抽象层，避免与厂商内置能力硬耦合；合同与合规侧确认数据出境与留存条款。
