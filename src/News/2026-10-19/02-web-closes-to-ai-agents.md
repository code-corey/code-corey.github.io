# Websites are closing their doors to AI agents（网站开始对 AI Agent 关门）

> 📅 2026-10-19 | 🏷️ 工程 & Agent | ⭐ HN 133分/125评论
> 🔗 原文：https://www.theverge.com/ai-artificial-intelligence/1013195/ai-agents-blocked-web
> 💬 HN 讨论：https://news.ycombinator.com/item?id=50141657

## 是什么

The Verge 报道的行业趋势：越来越多网站开始限制甚至彻底屏蔽 AI Agent 的访问。过去十年「反爬」针对的是抓内容的爬虫，现在针对的是会替用户浏览、比价、下单、填表的 Agent——网站不再只防「偷内容的」，还开始防「替人来办事的」。Agent 与开放 Web 的蜜月期出现拐点。

## 🔍 小白解读

### 先说几个词

- **AI Agent（智能体）**：能自己浏览网页、点按钮、完成多步任务的 AI 程序，像替你跑腿的私人助理。
- **爬虫（crawler）**：自动抓取网页内容的程序，搜索引擎的基石。
- **反爬 / anti-bot**：网站识别并拦截自动访问的技术，验证码是最常见的形态。
- **robots.txt**：网站声明「欢迎/不欢迎哪些自动访问者」的文本约定，君子协定。

### 这篇到底在说什么

网站以前欢迎爬虫，因为搜索引擎抓了内容会带来流量和广告收入。AI 时代游戏规则变了：AI 可以直接读走内容并总结给用户，用户不再点进网站，广告和订阅收入就断了。更进一步，Agent 不只是「看」，还会模拟真人去操作——比价、下单、抢票，网站承受成本却拿不到收益。于是越来越多网站选择直接识别并拒绝这类自动流量，The Verge 把这个趋势概括为「网站正在对 AI Agent 关门」。HN 上 133 分、125 条评论，讨论非常分裂：一边是内容网站的生存权，一边是「开放 Web 不该对工具关门」的老派理想，用户夹在中间。

### 这跟普通人有什么关系

你用的 AI 助理以后订票、比价、查资料可能更频繁地吃到验证码甚至直接被拒；你自建的自动化小工具也可能不知不觉被封。对靠网站获客的小生意，反倒可能是个「防 AI 白嫖」的新议题。

## 为什么值得架构师关注

若产品中存在「代表用户访问第三方站点」的能力（聚合比价、RPA、数据采集、Agent 浏览器），封锁是正在上升的架构风险：目标站点随时可能对 Agent 流量关闭，功能整体失效。应对思路三层：优先迁移到官方 API / 付费数据源，把「爬取」降级为兜底；为 Agent 流量做显式身份声明与限速，降低被封概率；设计降级路径——当站点拒绝 Agent 时，产品给用户什么。同时关注 Agent 准入与计费协议的演化（付费抓取、Agent 身份认证），这是未来 Agent 与 Web 交易的接口层，提前预留集成位。

## 核心内容

- The Verge 报道主题：websites are closing their doors to AI agents，网站对 Agent 流量的抵制成为显性趋势
- 屏蔽对象从「抓内容的爬虫」扩展到「替用户操作的 Agent」，性质从版权争议转向客户替代争议
- 矛盾核心：AI 总结与代理操作切走了网站的流量、广告与订阅收入
- HN 133 分 / 125 评论，社区在网站生存权与开放 Web 理想间立场分裂
- 本条同时出现在今日 Web3 技术讨论源中，显示其跨圈层热度

## 行动建议

要检查：盘点自家系统里所有「代替用户访问第三方网站」的功能，逐个确认服务条款边界与被封风险；高价值依赖优先换官方 API；为 Agent 出站流量加显式身份与限速；给核心链路设计「站点拒绝 Agent」时的降级方案。
