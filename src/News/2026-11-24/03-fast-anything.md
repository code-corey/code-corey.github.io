# Fast-Anything: Don't rewrite it in Rust. Rewrite the 5% that's slow（别全部重写成 Rust：只重写那慢的 5%）

> 📅 2026-11-21 | 🏷️ 值得研究的仓库 | ⭐ 3119（7天爆发）· 另见 HN 207分/170评论
> 🔗 原文：https://github.com/EL4CTEO/fast-anything

## 是什么

一个把「性能优化重写」工程化的开源工具（Rust 编写，创建于 2026-11-21，7 天内冲到 3119 star）。工作流：先对 Python / Node / Ruby 应用做性能分析（profile），找出最慢的 5% 热点函数，然后用你的编码智能体把这几个函数移植成 Rust 等更快实现，并**证明新实现与原实现行为一致**后才替换。

## 🔍 小白解读

### 先说几个词

- **Profile（性能分析）**：给程序做"体检"，记录每段代码花了多少时间。数据会告诉你：拖慢系统的往往只是一小段代码。
- **热点函数**：被反复执行、吃掉大部分运行时间的少数函数。经验上 5% 的代码常占 95% 的耗时。
- **FFI（外部函数接口）**：让 Python/Node 等语言调用 Rust 编写的高性能代码的"插座"。
- **行为等价验证**：证明替换前后程序输出完全一样。好比换发动机前先在试验台证明新引擎和旧引擎输出功率一致。
- **编码智能体**：能自主读写代码、跑测试的 AI 编程工具（如 Claude Code、Codex 类）。

### 这篇到底在说什么

工程师圈子里有个老争论：系统太慢，要不要把整个项目用 Rust 重写一遍？全量重写风险极高——周期长、引入新 bug、业务停摆。这个项目提出的答案是：**别动另外 95%，只换最慢的那 5%**。流程分三步：第一步，用工具给程序做"体检"，自动找出最拖速度的少数函数；第二步，把这个函数连同它的调用方式交给你的 AI 编程助手，让它用 Rust 重写一个等价版本；第三步，也是最关键的，工具会验证新写的代码和原来行为完全一致，通过了才允许替换上线。AI 编程助手恰好擅长这种"目标明确、范围很小、有测试兜底"的移植活。这个定位切中了当前 AI 辅助重构的最大痛点：怎么敢把 AI 改的代码放进生产环境。

### 这跟普通人有什么关系

如果你维护着一个越跑越慢的老系统，这套思路意味着：不用推倒重来，也不用高薪外包重写，用工具找出瓶颈、让 AI 换掉那一小块，系统就能明显提速，而且有验证机制保证不出幺蛾子。

## 为什么值得架构师关注

这是一条**渐进式迁移**的完整范式：profile 定位 → AI 移植 → 等价性验证 → 局部替换。它把"AI 写的代码敢不敢上线"这个问题转化为可验证命题，与团队现有的 CI 门禁天然兼容。对技术债重的 Python/Ruby 服务，这是比微服务化、全量重写成本低一个数量级的优化路径。同时注意评估其验证机制的覆盖度（边界条件、并发、异常路径）——等价性证明的严格性决定了这套流程的信任上限。

## 核心内容

- 支持 Python / Node / Ruby 三种生态的热点分析，输出需移植的函数清单。
- 与编码智能体协同：由智能体完成热点函数的 Rust 移植，人工审核后替换。
- 内置行为等价性验证，证明新实现与原实现输出一致，作为替换前置条件。
- 创建于 2026-11-21，7 天 3119 star、语言 Rust，增速远超同期仓库。

## 行动建议

选一个 profile 下 P95 延迟不达标的 Python 服务试用：先跑热点分析，挑一个纯计算型热点函数走完整流程，重点审查其等价性验证对边界条件的覆盖；若验证可信，可纳入性能优化标准作业流程，并沉淀 FFI 封装规范。
