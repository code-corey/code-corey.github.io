# MyAgent：从零实现的通用 Agent Runtime（Agent Loop、权限、MCP、子 Agent、上下文折叠）

> 📅 2026-10-16 | 🏷️ 值得研究的仓库 | ⭐ 145（7天）
> 🔗 原文：https://github.com/ztt0216/MyAgent

## 是什么

MyAgent 是一个从零实现的通用 Agent Runtime（智能体运行时），把当前 agent 工程的六大核心组件——Agent Loop（主循环）、权限控制、MCP 协议接入、子 Agent 调度、上下文折叠、Skills 自进化——全部亲手实现了一遍。它不是又一个封装好的 agent 产品，而是一份可以逐行阅读的"参考架构"，仓库 7 天收获 145 星，创建于 2026-10-16。

## 🔍 小白解读

### 先说几个词

- **Agent Runtime**：让 AI 智能体"活着干活"的底层系统，负责安排它每一步做什么、能用什么工具——相当于智能体的操作系统。
- **Agent Loop（主循环）**：智能体的基本工作节奏——想一下、动一下、看结果、再想一下，循环往复直到任务完成，像人"查资料→动手→检查→再改"的过程。
- **子 Agent**：主 agent 派出去干分支任务的"小弟"，各干各的，干完汇报，避免一个大脑被所有杂事挤爆。
- **上下文折叠（context folding）**：对话历史太长时把旧内容压缩成摘要，只留重点——像把读完的章节合上，只在书签上写要点。
- **Skills 自进化**：智能体把干过任务的经验沉淀成可复用的"技能卡"，下次同类任务直接调用，越用越熟练。

### 这篇到底在说什么

打个比方：市面上的 agent 产品像一台台成品汽车，而 MyAgent 是有人把发动机、变速箱、底盘全部拆开、每个零件手工造了一遍，还附上了图纸。你想知道"agent 循环到底怎么写的""权限是怎么在每一步工具调用前卡住的""上下文太长怎么办"，翻它的代码就能看到最简可行版本。这类仓库的价值不在功能多强，而在"透明"——商业产品把实现藏着掖着，它把骨架摊开给你看。对想真正理解 agent 内部机制的人来说，读一遍这种从零实现，比看十篇综述文章都扎实。

### 这跟普通人有什么关系

对普通开发者，这是理解"AI 助手为什么有时聪明有时犯傻"的捷径——你知道了它的循环和记忆机制，就知道怎么写提示词、怎么拆任务能让它表现更好。对想转 agent 方向的工程师，这是一份现成的学习地图：六个组件就是六节课的目录。

## 为什么值得架构师关注

- **自研 agent 平台的参考骨架**：团队自建 agent 平台时，六大组件（Loop/权限/MCP/子 Agent/上下文折叠/Skills）就是最小完备集的直接参照，可据此评估商业框架的功能覆盖率。
- **上下文折叠与 Skills 自进化是差异化看点**：多数开源实现止步于 Loop+工具调用，这两个组件对应长任务稳定性与组织知识沉淀，是 agent 从 demo 走向生产的分水岭。
- **教学级代码的可维护性取舍**：从零实现便于学习，但生产落地仍需对照主流框架的工程化补齐（重试、观测、沙箱），避免直接搬用。
