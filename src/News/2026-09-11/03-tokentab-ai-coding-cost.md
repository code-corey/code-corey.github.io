# crwdla/tokentab：AI 编码会话成本核算 CLI（tokentab）

> 📅 2026-09-11 | 🏷️ 值得研究的仓库 | ⭐ ⭐239（7 天）
> 🔗 原文：https://github.com/crwdla/tokentab

## 是什么

tokentab 是一个 Python 写的命令行工具：读取 **Claude Code、Codex、Gemini CLI** 的本地会话日志，自动算出你（或你的团队）的 AI 编码到底花了多少钱——并且能按**模型、项目、天**三个维度拆开。仓库创建于 2026-09-07，7 天内拿下 239 星。

## 🔍 小白解读

### 先说几个词

- **CLI（命令行工具）**：在终端里敲命令运行的小程序，不需要图形界面，适合开发者日常挂在工作流里。
- **会话日志（Session Logs）**：AI 编码助手每次帮你干活都会在本地留下记录（聊了什么、用了哪个模型、消耗了多少 token），tokentab 的原料就是这些日志。
- **Token**：大模型计费的最小单位， roughly 相当于一个单词或几个汉字。你花的钱 = token 用量 × 单价。
- **FinOps**：把「云/AI 花销」当成财务问题来管理的方法论——先看得见，才谈优化。

### 这篇到底在说什么

打个比方：家里的电表如果只显示总读数，你永远不知道是空调还是热水器在吃电。tokentab 就是给 AI 编码装了一块分路电表：它不改变你用 Claude Code / Codex / Gemini CLI 的任何习惯，只是事后把本地日志翻出来，告诉你「这个月、这个项目、这个模型，分别烧了多少钱」。7 天 239 星说明「AI 编码到底花了多少冤枉钱」是大量团队的共同焦虑。

### 这跟普通人有什么关系

如果你的公司按人头给开发者配了 AI 编码订阅或 API 额度，这个工具能帮你回答「这钱花得值不值」；个人开发者也能用它避免月底账单惊魂。

## 为什么值得架构师关注

1. **AI 编码成本治理的第一步是度量**：在做「哪些场景该用贵模型、哪些该降级到便宜模型」的决策前，先要有按模型/项目/天维度的真实用量数据——tokentab 提供的正是这个最小闭环。
2. **多供应商混合现实**：团队同时用 Claude Code + Codex + Gemini CLI 已是常态，分散日志导致成本黑洞；统一口径的核算工具是混合策略的前提。
3. **本地数据、零侵入**：工作方式是读本地日志而非接管请求链路，不引入代理层延迟与隐私风险，适合直接推给团队自查（工具细节与隐私边界以仓库文档为准）。

## 行动建议

怎么评估试用：在一台开发机上跑一周历史日志，核对与账单的误差；误差可接受后接入团队，把「按项目成本」纳入双周研发例会。若团队重度依赖订阅制（而非按 token 计费），先用它看用量分布，成本结论再结合订阅价计算。
