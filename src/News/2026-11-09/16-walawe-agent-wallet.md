# Walawe: Open-source wallet & API gateway for autonomous AI agents（面向自主 AI Agent 的钱包与 API 网关）

> 📅 2026-11-09 | 🏷️ Web3 & Crypto | ⭐ 2（7 天窗口 · 极早期雷达条目，问题独特） | 语言：Go
> 🔗 原文：https://github.com/pikcui/Walawe

## 是什么

Walawe 是一个开源（Go 实现）的钱包与 API 网关项目，专为自主运行的 AI Agent 设计：提供确定性预算（deterministic budgets）、人工审批（human approvals）、x402 支付协议和 ERC-4337 智能账户。仓库 11 月 5 日创建、目前仅 2 星，属于极早期项目——但其瞄准的问题（AI Agent 如何安全地花钱）正是 Web3×AI 交叉方向最关键的缺失基础设施之一。

## 🔍 小白解读

### 先说几个词

- **自主 AI Agent 的支付问题**：让 AI 替你干活容易，让它替你花钱危险。没有「花钱围栏」的 Agent 是企业不敢上生产的头号原因之一。
- **确定性预算**：给每个 Agent 预先划死花钱额度——不管 AI 怎么「自主决策」，超出预算的支付在协议层面就发不出去，而不是靠提示词恳求它别乱花。
- **x402**：一个基于 HTTP 402 状态码的互联网原生支付协议（由 Coinbase 主导开源），让 API 调用可以按次自动小额付费——机器对机器付款的标准尝试。
- **ERC-4337（账户抽象）**：以太坊的「智能钱包」标准，钱包本身是合约，可以编程序——比如设置每日限额、多签审批、把「谁有权花钱」写成代码。

### 这篇到底在说什么

行业现在很擅长让 AI Agent 干活，但在「让 Agent 自己付钱」这件事上一直很犹豫——一旦接上支付能力，一个被提示词注入攻击的 Agent 或一个逻辑跑偏的 Agent 可能把预算烧光。Walawe 的方案思路是把「花钱的围栏」做在基础设施层：每个 Agent 有确定性预算，超限支付直接被网关拦截；关键支付走人工审批；协议层采用 x402 让按次付费标准化；底层账户用 ERC-4337 智能合约钱包，把限额规则写进链上代码。打个比方：它不是给实习生一张无限额度的公司卡再叮嘱「省着点花」，而是直接发一张只能刷特定类别、每日限额、大额消费要打电话给老板确认的子卡。2 星的仓库谈不上成熟，但这个架构组合（预算 + 审批 + x402 + 4337）几乎复刻了企业财务管控的最佳实践，方向判断是对的。

### 这跟普通人有什么关系

未来你会遇到越来越多「替你买东西、付订阅费」的 AI 助手。你该问的第一个问题就是：它的花钱额度谁控制、超支了怎么办。这类基础设施的成熟，直接决定你敢不敢把支付权限交给 AI。

## 为什么值得架构师关注

- **Agent 支付是生产落地的缺失环节**：企业 Agent 要碰真实交易，必须有协议层的支出围栏，提示词级别的约束不可审计也不可靠。
- **架构组合值得借鉴**：确定性预算（硬拦截）+ 人工审批（例外通道）+ x402（按次计费标准）+ ERC-4337（可编程账户）的四层设计，可以整体或拆解移植。
- **与本期 AI 侧动态呼应**：DeepSeek Agent 平台日活 154 万并筹备插件市场——Agent 规模化使用在先，支付基础设施必须跟上，这个交叉赛道的时间窗口正在打开。
- **极早期项目的正确用法**：2 星意味着代码未经社区检验，适合源码级研究与架构参考，不适合直接生产采用。

## 核心内容

- 定位：为自主 AI Agent 提供钱包与 API 网关，开源、Go 实现。
- 核心能力：确定性预算、人工审批、x402 支付协议、ERC-4337 智能账户（项目官方描述）。
- 解决的核心问题：Agent 自主花钱的安全围栏，从提示词约束升级为基础设施约束。
- 仓库创建于 2026-11-05，目前 2 星，属于 Web3×AI 交叉方向的极早期雷达条目。

## 行动建议

1. 源码级研究其预算拦截与审批流的设计，即使不用该项目，其四层架构也值得吸收进自研 Agent 支付规范。
2. 若正在设计企业内 Agent 的支出管控，对照评估「确定性预算 + 例外审批」是否优于当前的纯审批制。
3. 了解即可：项目极早期，列入观察清单，待其获得社区检验或替代方案出现后再评估采用。
