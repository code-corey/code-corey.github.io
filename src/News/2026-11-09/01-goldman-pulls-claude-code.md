# Goldman Sachs is pulling Claude Code from its bankers and traders（高盛从银行家与交易员团队撤回 Claude Code）

> 📅 2026-11-08 | 🏷️ 工程 & Agent | ⭐ HN 562分/338评论
> 🔗 原文：https://www.thestateofai.com/news/goldman-sachs-claude-code-traders-bankers

## 是什么

据报道，高盛（Goldman Sachs）正在把 AI 编码智能体 Claude Code 从其银行家与交易员团队中撤回。该消息在 Hacker News 上引发大范围讨论（562 分、338 条评论），成为本周末企业级 AI 工具治理话题的焦点。这是目前公开报道中最具代表性的「一线投行收回 AI 编码工具」事件之一。

## 🔍 小白解读

### 先说几个词

- **Claude Code**：Anthropic 推出的命令行 AI 编码智能体，能读写代码、执行命令、自动完成多步编程任务，不只是「补全代码」，更像一个能干活的数字实习生。
- **编码智能体（Coding Agent）**：能自主规划步骤、调用工具、修改文件的 AI 程序。和「问答式 AI」的区别是它会真的动手改你的系统。
- **合规红线**：金融行业对「什么数据能被什么系统看到、什么代码能被部署」有一整套强制规定，违反了会面临监管处罚。
- **影子 IT**：员工绕过 IT 部门私自使用未经审批的工具。AI 工具普及后，这是企业安全的重灾区。

### 这篇到底在说什么

打个比方：公司请了一批很能干的实习机器人帮老员工写代码，用了一段时间后，管理层突然说「银行和交易这两个最重要的部门，先把机器人收回来」。高盛正是这样做的——据这篇报道，Claude Code 被从银行家（bankers）和交易员（traders）团队撤下。这两类岗位处理的是金融机构里最敏感的信息：客户交易、并购信息、市场持仓，任何一条泄漏出去都可能引发内幕交易嫌疑或巨额损失。消息在 Hacker News 上引发 338 条评论的激辩，支持者认为金融数据碰不得，反对者认为这是开倒车——不用 AI 的银行反而会在效率上被对手甩开。无论立场如何，这件事说明：企业采用 AI 编码工具已经不是「要不要用」的问题，而是「谁能用、在哪里用、数据去哪里」的治理问题。

### 这跟普通人有什么关系

如果你所在的公司正在推广 AI 编码工具，这件事是一个提醒：工具能力再强，也要先搞清楚公司的数据分级和使用政策，别把敏感业务数据喂给未经审批的服务。对普通开发者来说，金融、医疗、政务等强监管行业的 AI 工具准入会更慢、更严格，选工作时这反而是个可以关注的方向。

## 为什么值得架构师关注

- **企业 Agent 落地的瓶颈在治理而非模型**：一线投行主动收回工具，说明合规审计、数据边界、审计日志等治理能力必须先于工具铺开。
- **工具选型要预设「退出机制」**：连头部客户都会撤回工具，选型时必须评估代码库迁移成本、数据驻留方案和多供应商备份。
- **岗位分级授权是必答题**：交易、并购等高敏感岗位与前中后台的 AI 工具权限应该差异化管理，而不是一刀切或一刀放。
- **影子 IT 风险敞口**：员工个人账号使用 AI 工具处理公司代码的情况需要盘点，这也是企业级 API 网关与审计方案的需求来源。

## 核心内容

- 据报道，高盛将 Claude Code 从银行家与交易员团队撤回，属于企业级 AI 编码工具的收缩性调整。
- 事件在 Hacker News 获 562 分、338 条评论，讨论焦点集中在金融数据安全与企业 AI 治理。
- 被撤回的两类岗位（投行 banker、交易员）是金融机构中信息敏感度最高的角色。
- 该报道引发的企业 AI 工具治理讨论，与近期 AI 工具在企业内「先铺开、后补治理」的普遍模式形成对照。

## 行动建议

1. 盘点本组织内 AI 编码工具的使用范围，确认是否存在覆盖高敏感系统却无数据分级授权的情况。
2. 在工具选型文档中补充「撤回预案」：导出、迁移、数据清除的具体流程与成本估算。
3. 关注事件后续一手信息（高盛官方声明或 Anthropic 回应），目前仅有二手报道口径，暂不宜直接作为决策依据。
