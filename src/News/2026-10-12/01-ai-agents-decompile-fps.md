# 500B tokens later: Letting AI agents decompile a first-person shooter（5000 亿 token 之后：让 AI Agent 反编译一款 FPS 游戏）

> 📅 2026-10-11 | 🏷️ 工程 & Agent | ⭐ HN 143分/106评论
> 🔗 原文：https://momo5502.com/posts/2026-10-09-game-decompilation/

## 是什么

独立开发者 momo5502 发布的一篇长文复盘：让 AI coding agent 持续对一款商业第一人称射击游戏做反编译（decompilation），累计消耗约 5000 亿（500B）token。文章记录了这条「agent 干重活」路线的可行边界、成本量级和踩坑经验，在 HN 引发了 100+ 条关于 agent 长任务工程的实质讨论。

## 🔍 小白解读

### 先说几个词

- **反编译（decompilation）**：把编译好的游戏程序「逆向翻译」回接近源代码的形式。打个比方：成品蛋糕没法变回面粉和鸡蛋的精确配方，但反编译就是尽力把配方猜出来，让后人能重烤一个一样的蛋糕。
- **AI Agent**：不只回答问题、还能自己动手干活的 AI——它能调用工具、读写文件、跑命令，把一个大任务拆成许多小步骤自己推进。
- **Token**：AI 处理文本的最小计费单位，大约相当于一个单词或半个汉字。5000 亿 token 的消耗量，相当于让 AI 读完几十万本长篇小说的工作量。
- **上下文窗口（context window）**：AI 一次能「记住」的内容上限，像一个只有固定大小的书桌，放不下的资料就得收进抽屉。

### 这篇到底在说什么

游戏公司发布游戏时，发布的是「编译后」的机器码，人类几乎没法直接读懂。作者想做的事情是把一款 FPS 游戏逆向成可读、可改的代码——过去这需要顶级逆向工程师团队干上几个月甚至几年。这次他换了一种做法：把任务交给 AI agent，让它自己反复读汇编代码、猜测变量含义、重写函数、编译验证，循环往复。整个过程累计烧掉了约 5000 亿 token——这是一个前所未有的公开成本数据点。文章的价值不在于「AI 能不能反编译游戏」这个答案，而在于它是一个真实、完整的 agent 长任务案例：任务周期长、步骤多、中间会出错、需要验证机制兜底。HN 讨论区里大量从业者围绕「这个成本划不划算」「什么样的任务适合交给 agent 长跑」展开了激烈辩论。

### 这跟普通人有什么关系

如果你是普通开发者，这条新闻说明「用 AI 干编程重活」已经从尝鲜进入量产阶段，但成本不再是免费的——理解 token 消耗量级会成为基本功。如果你是打工人，你所在公司未来用 agent 承接的老系统维护、代码迁移类工作，大概率会参考这类公开经验来设计流程。

## 为什么值得架构师关注

1. **成本锚点**：500B token 是极少数公开的 agent 长任务消耗数据。做 agent 立项预算时，终于有了一个「重体力逆向工程任务」的真实量级参照，而不是拍脑袋。
2. **任务形态判断**：反编译任务的特点是「可自动验证」（重写后能编译、能跑、能对比行为）——这正是 agent 长任务成功率最高的任务形态。选型时应该优先找有客观验证回路的工作，而不是开放式创造性工作。
3. **人机分工设计**：作者的做法印证了当前的共识架构——agent 负责批量猜测与重写，人类负责关键决策与抽查。这个分工比例是所有 agent 落地项目都要回答的问题。
4. **失败模式积累**：长周期任务里 agent 会「自信地跑偏」，这类复盘文章提供的失败案例比成功案例更有参考价值。

## 核心内容

- 作者让 AI agent 持续执行一款 FPS 游戏的反编译任务，累计消耗约 5000 亿 token，并公开了完整过程记录。
- 任务的推进模式是「读机器码 → 猜测语义 → 重写为可读代码 → 编译/运行验证」的循环，agent 在循环中承担主要体力工作。
- 500B 的量级说明这类任务的算力成本已经进入「可与人力成本对赌」的区间，但前提是任务可验证、可中断、可续跑。
- HN 讨论集中于成本合理性、token 消耗的统计口径，以及「哪些任务适合 agent 长跑」的边界划分，讨论质量较高。

## 行动建议

1. 若团队有老系统逆向、协议还原、遗留代码迁移类需求，值得精读原文，重点看作者如何设计验证回路与断点续跑机制。
2. 把「任务是否可自动验证」加入 agent 项目的立项检查清单，不可验证的任务先降级为「agent 辅助 + 人工验证」模式。
3. 用 500B token 这个数据点重新校准团队的 agent 预算模型，在POC 阶段就记录 token 消耗曲线。
