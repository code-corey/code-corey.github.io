# Declare is a UI language for you and your AI（Declare：为你和你的 AI 设计的 UI 语言）

> 📅 2026-11-24 | 🏷️ 工程 & Agent | ⭐ HN 105分/92评论
> 🔗 原文：https://davidtemkin.github.io/declarelang/
> 💬 HN 讨论：https://news.ycombinator.com/item?id=50622854

## 是什么

Declare 是一门新的声明式 UI 语言，定位是「为你和你的 AI 同时设计」：人类用它声明界面意图与结构，AI 则能可靠地解析、生成和修改它。项目由 David Temkin 发布在 GitHub Pages 上，HN 获得 105 分 / 92 条评论，是本周「AI 时代要不要重新发明前端 DSL」讨论的代表作。

## 🔍 小白解读

### 先说几个词

- **声明式语言（Declarative）**：你只说"要什么"（一个带搜索框的商品列表），不说"怎么做"（先建 div、再绑事件）。HTML、SQL 都是声明式的。
- **DSL（领域专用语言）**：为特定领域量身定做的语言，比如专门管数据库的 SQL、专门管构建的 YAML 管道配置。
- **代码生成确定性（Determinism）**：AI 生成代码时，输入相同、输出结构是否稳定可预测。DSL 越规范，AI 越不容易"自由发挥"跑偏。
- **意图（Intent）**：你真正想达到的目的，而不是实现细节。"展示最近 7 天订单"是意图，写 50 行 React 是实现。

### 这篇到底在说什么

打个比方：现在的 AI 写前端，像让一个外国工人照着口头描述砌墙——中间隔着一层语言翻译，容易砌歪。Declare 的思路是把"描述界面的话"本身做成一门规范语言：人说人话（接近自然意图），AI 读规范（结构明确、歧义少）。因为声明式语言的语法是收敛的、可校验的，AI 生成时犯错的自由度被大幅压缩，改起来也更像"改参数"而不是"重写代码"。HN 评论区的争论焦点在于：我们已经有 HTML/JSX/各种低代码，再发明一门语言是否必要——支持者认为 AI 原生的 DSL 会让人机协作成本更低，反对者认为这是第 N 次"发明 HTML"。

### 这跟普通人有什么关系

如果这类「AI 友好 UI 语言」成熟，未来不懂编程的人描述界面就能得到可用的应用原型；对开发者则意味着前端工作重心从"写组件"转向"审校与定义规范"。

## 为什么值得架构师关注

1）**前端架构的 AI 适配层**：如果 AI 生成 UI 成为默认路径，DSL 是控制生成质量与可维护性的手段之一，值得跟踪 Declare 的语法设计与 AI 迭代体验；2）**与设计系统的关系**：声明式意图层 + 组件库 = 可控的 AI 生成管线，比"直接生成 React 代码"更可治理；3）**风险提示**：新 DSL 意味着新工具链与迁移成本，团队采用前先评估生态成熟度——本项目目前是个人项目形态（GitHub Pages 发布），非生产级框架。

## 核心内容

- Declare 是一门声明式 UI 语言，官方定位是「for you and your AI」：人类表达意图、AI 负责生成与修改。
- 核心机制：用规范化的声明语法压缩 AI 生成的歧义空间，让"改界面"更接近改声明而非重写代码。
- 项目地址：davidtemkin.github.io/declarelang，个人项目形态发布。
- 社区热度：HN 105 分 / 92 评论，争论点集中在「是否需要第四代 UI 语言」与 AI 原生 DSL 的实际收益。

## 行动建议

值得花 30 分钟读一下语法设计并试玩示例，重点观察：AI 修改声明时的准确率与失控率。暂不建议在任何生产链路采用；可将其思路（意图层 → 生成层分离）借鉴到自有低代码/AI 生成管线的架构讨论中。
