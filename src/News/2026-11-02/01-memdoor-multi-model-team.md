# Memdoor: A team of 5 Qwen3.8-27B models beats Fable 5 on LiveCodeBench Hard（5 个 Qwen3.8-27B 组队击败前沿模型）

> 📅 2026-10-31 | 🏷️ 工程 & Agent | ⭐ HN 420 分 / 205 评论
> 🔗 原文：https://github.com/guregodevo/memdoor/tree/main/examples/workflows/team-solve
> 💬 HN 讨论：https://news.ycombinator.com/item?id=50320995

## 是什么

开源项目 Memdoor 的 team-solve 示例工作流展示了一种「以量取胜」的解题路线：让 5 个中等规模开源模型 Qwen3.8-27B 组成团队，通过分工协作共同解答编程题。据项目方公布的对比结果，这套组合在高难度代码基准 LiveCodeBench Hard 上击败了单个前沿闭源模型 Fable 5。该结果在 Hacker News 上获得 420 分和 205 条评论，讨论相当热烈。

## 🔍 小白解读

### 先说几个词

- **Qwen3.8-27B**：阿里通义千问系列的 270 亿参数开源模型。「27B」指参数量约 270 亿，属于中等规模——比手机能跑的大，但远小于顶级闭源模型。
- **LiveCodeBench Hard**：一个持续更新的代码能力评测基准，「Hard」是其中的困难档，题目接近算法竞赛难度，用来检验模型真实的编程水平。
- **Fable 5**：当前一代的前沿闭源模型（类似 GPT/Claude 档位的商业模型），单个调用价格远高于 27B 级开源模型。
- **team-solve（组队解题）**：把一道难题拆给多个模型实例，让它们各自尝试、互相校验，最后汇总出答案——类似让 5 个中学生组成小组和 1 个学霸比赛做题。
- **开源模型**：权重可以下载到自己服务器上运行的模型，数据不出门，按算力付费。

### 这篇到底在说什么

打个比方：以前大家都默认「想赢奥数题就得请金牌教练」，也就是用最贵最强的前沿模型。Memdoor 这个项目说：我们让 5 个普通水平的模型组成解题小组，分头审题、互相挑错、汇总答案，结果在很难的编程题测试里真赢了单个金牌教练。这件事的震撼点不在「谁赢了一场」，而在于它挑战了一个选型直觉——**模型能力不足时，是不是只能买更贵的模型？多模型协作可能是另一条路**。当然，HN 上 205 条评论里也有大量质疑：评测是否公平、协作的成本（5 个模型的 token 消耗）有没有算进去、结果能否复现，这些都需要独立验证。

### 这跟普通人有什么关系

对普通开发者来说，这意味着用本地或低价 API 部署的中小模型，通过合理的编排方式也可能完成过去必须用顶级模型才能干的活，直接降低 AI 工具的使用门槛和费用。对小公司而言，「买不起最强模型」可能不再是做不出高质量 AI 功能的理由。

## 为什么值得架构师关注

- **选型维度变化**：编码 agent 的选型矩阵里出现新选项——「1×前沿模型」vs「N×中档模型 + 编排层」，后者的单次成本结构完全不同（便宜但调用次数多），需要实测 token 总账。
- **成本弹性**：27B 级开源模型可以私有化部署，团队规模扩大时成本是线性的算力扩展，而不是订阅费跳档；这对预算受控的企业落地很关键。
- **编排层价值上升**：如果「小模型组队」路线成立，团队的核心工程资产就从「选哪个模型」变成「怎么编排协作」，这部分是自有代码，不锁定在任何厂商。
- **风险提示**：单一项目公布的结果需独立复现，HN 讨论中存在对评测公平性的争议，暂不宜据此做替换决策。

## 核心内容

- Memdoor 仓库的 `examples/workflows/team-solve` 工作流实现了多模型团队解题机制。
- 公布的对比结果：5 × Qwen3.8-27B 协作在 LiveCodeBench Hard 上超过单个前沿模型 Fable 5。
- Qwen3.8-27B 是 HF 趋势榜热门模型（当前 18,926 赞 / 789 万下载），社区采用基础扎实。
- HN 420 分 / 205 评论，是近 48h 编码 agent 方向讨论量最高的话题。
- 结果尚待第三方复现，HN 评论区对评测方法存在明显争议。

## 行动建议

不要据此立刻更换编码 agent 选型。建议：① 用团队真实任务样本小规模复现 team-solve 模式，记录总 token 成本与耗时；② 与当前单个前沿模型方案做同题对比；③ 复现结果可靠且成本占优时，再考虑在低风险内部任务上灰度。
