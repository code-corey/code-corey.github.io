# Multi-Token Prediction Done Right（把多 Token 预训练做对）

> 📅 2026-11-02 | 🏷️ 前沿论文 | ⭐ HF upvotes 17
> 🔗 原文：https://huggingface.co/papers/2610.38331

## 是什么

多 Token 预测（Multi-Token Prediction, MTP）已成为大模型预训练的常见配料：它既能提升下游能力，又能通过投机解码加速推理。这篇论文发现了标准 MTP 训练中的一个**梯度缺陷**：MTP 损失的梯度中有一个「残余分量」，会同时干扰 next-token 预测和多 token 学习，而且模型规模越大干扰越严重。作者把 MTP 的交叉熵梯度精确分解为一个 KL 自蒸馏项（把每个 MTP 头拉向模型自己的 next-token 分布，这一项反而有助于投机解码）和这个有害残余项，据此给出修正做法。HF upvotes 17，是本期训练方法类论文中讨论度最高的之一。

## 🔍 小白解读

### 先说几个词

- **Next-Token 预测（NTP）**：大模型的基本功——给前文，猜下一个字。GPT 类模型全靠这个练出来。
- **多 Token 预测（MTP）**：不止猜下一个字，一次猜后面好几个字。练这个能让模型「看得更远」，还能服务加速。
- **投机解码（speculative decoding）**：推理加速技术——先用便宜的「草稿」猜一串字，再让大模型一次性核对，对就采纳，错就重来。类似口译员先小声预翻、领导点头后正式说出来。
- **KL 散度**：衡量两个概率分布差异的数学工具，训练里常用来「让 A 向 B 看齐」。
- **梯度**：训练时模型「往哪边调参数」的方向指示。梯度里混进坏信号，模型就会被带偏。

### 这篇到底在说什么

打个比方：学生（模型）平时练「猜下一个字」（NTP），后来加了一门新课「一次猜一串字」（MTP）。大家发现新课有用，但这篇论文发现：**新课的作业里混进了一份「错误答案册」**——梯度里有个残余分量在悄悄干扰两门课的学习，而且学生越厉害（模型越大）受害越深。作者做了一件很漂亮的事：把作业精确拆开，发现其中一部分其实是「自查自纠」（KL 自蒸馏，让多 token 头向模型自己的 next-token 判断看齐），这部分不但无害，还能让投机解码更快；剩下的才是真正的有害部分。拆开之后去掉坏的、保留好的，就是「把 MTP 做对」。

### 这跟普通人有什么关系

普通用户不会直接碰训练代码，但这项修正会传导到下一代开源模型：同尺寸模型质量更好、推理更快（投机解码更有效），意味着以后本地跑的模型更聪明、更省电、更便宜。

## 为什么值得架构师关注

- **下一代基座的成本曲线**：MTP 修正版如果被主流预训练配方采用，同质量模型的推理吞吐会提升（投机解码路径），直接影响推理服务的 GPU 成本规划。
- **自研训练团队的 checklist**：做继续预训练/领域微调且启用了 MTP 的团队，应对照论文检查自己的梯度实现是否包含该干扰项。
- **推理侧联动**：KL 自蒸馏项「改善投机解码」的结论，提示推理加速方案的参数（草稿头与目标模型的耦合方式）有优化空间。
- **选型信号**：未来评估开源新模型时，「是否采用修正版 MTP」可作为训练配方先进性的判断点之一。

## 核心内容

- 发现标准 MTP 训练的梯度缺陷：一个残余分量同时干扰 NTP 与 MTP 学习，且随模型规模增大而加剧。
- 将 MTP 交叉熵梯度精确分解：一个 KL 自蒸馏项（MTP 头向模型自身 next-token 分布看齐）+ 有害残余项。
- 该 KL 自蒸馏项不仅无害，还能改善投机解码效果。
- 论文给出修正后的 MTP 训练做法（「done right」版本）。
